# 自动化核心接口契约

## 输入边界

游戏层只负责生成不可变 `HouseSnapshot`。未知字段必须用 `null/Unknown`，不得伪装成 0。稳定猫 ID、稳定房间 ID、场景 generation 和 game build 是写操作的硬前置。

## 处理管线

```text
HouseSnapshot
  -> CombatScorer
  -> BreedingScorer
  -> ProtectionPolicy
  -> Classifier
  -> RoomPlanner
  -> OrganizePlan（只读预览）
  -> Executor（项目内另行连接游戏写适配器）
```

## 硬约束

- 战斗评分只评价单只猫。
- 保护优先于黑名单、评分和容量释放。
- `NoCull` 不可淘汰；`NoMove` 不可移动；`FullyUnmanaged` 不参与自动管理。
- 置信度不足时不得进入破坏性候选。
- 房间规划不得超过已知硬容量。
- 房间不足允许部分成功，不能隐式删除猫。
- 淘汰候选与实际淘汰分离。
- 规划器无游戏写接口。

## 输出

`OrganizePlan` 至少包含：

- 算法版本；
- 源快照 ID；
- 每只猫的战斗/繁育分数与解释；
- 主角色和保护级别；
- 推荐战斗猫；
- 质量淘汰候选；
- 容量释放候选；
- 房间移动差异；
- 未安置猫；
- 警告；
- `fully_satisfied`。
