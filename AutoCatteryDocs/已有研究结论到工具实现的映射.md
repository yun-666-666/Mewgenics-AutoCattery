# 已有研究结论到工具实现的映射

本文件不包含新研究，只记录如何把此前结论落到工具中。

| 已有结论 | 工具实现 |
|---|---|
| 猫需要稳定 ID、属性、能力、突变、关系和房间数据 | `house_snapshot.schema.json`、`domain.hpp` |
| 战斗猫只按独立评分，不自动组队 | `ScoreCombat`、`never auto-select` 硬规则 |
| 繁育价值与战斗价值可并存 | `CatDecision` 同时保存两个分数和多个布尔成员身份 |
| 保护规则必须优先 | `ProtectionLevel`、`CanCull`、`CanMove` |
| 房间容量、舒适度和用途需要进入规划 | `RoomPlanningConfig`、`PlanRooms` |
| 房间不足不能随意删猫 | `unplaced_cats`、`capacity_relief_culls`、部分成功 |
| 真实写入需要备份和回滚 | 16 步文档第 10、14 阶段；参考核心本身不提供写接口 |
| 游戏更新时应只读降级 | 仓库规则和第 15 阶段门禁 |
| Codex 应分步执行以减少失败和 Token 浪费 | `auto_cattery_codex.py`、`CODEX_TASK.md`、阶段状态 |
