# 第 07 阶段：繁育猫评分、分类与淘汰候选生成

## 文档定位

建立繁育评分和“候选淘汰”决策，但不实际淘汰。战斗猫仍只按独立评分。

## 固定技术基线

- 主路线：Windows x64 原生 DLL MOD。
- 运行时加载器：**Mewjector**。
- 游戏内 UI：**MewUI API**，以源码依赖方式编译进本 MOD。
- 可选安装管理器：Mewtator，仅用于安装和启停，不属于硬依赖。
- 参考实现：
  - Quick-Cleanup：参考“家园场景注入按钮并触发一次性操作”。
  - Mewgenics Breeding Manager：参考猫评分、血缘/近亲检查、房间优化、文件竞态处理；只能复用许可证允许的代码。
  - Online Savegame Editor：参考 `.sav` 解析、SQLite/LZ4、dirty tracking、备份和安全写回。
  - Mewgenics QoL Manager：仅参考批量筛选、房间移动、符号标记的交互思路。
  - MewgenicsModTool：仅作为“实时读取、推荐、cull 可行”的能力证据；未获许可时不得复制代码或资源。
- 不采用“自动组队策略”。战斗猫只按独立评分排序和标记，不分析职业搭配、站位或队伍协同。
- 两个主动按钮：
  1. 家园界面：`自动整理猫舍`。只有玩家点击后才分析、分类、淘汰和调整房间。
  2. 次日出征/选猫界面：`标记推荐战斗猫`。点击后只高亮高评分猫，不自动选队。

## 分类目标

每只猫可拥有多个评分，最终由分类器给出主角色：

- `CombatRecommended`
- `BreedingCore`
- `BreedingReserve`
- `GeneralReserve`
- `CullCandidate`
- `ProtectedUnmanaged`
- `Ineligible`

战斗高分不自动排除繁育价值；冲突用配置化优先级解决。

## 繁育评分

参考 Breeding Manager 的思想，但不要假设其全部字段都能直接复用。建议：

```text
BreedingScore = BaseStatPotential
              + RareGeneValue
              + AbilityInheritanceValue
              + DiversityValue
              + Age/FertilityValue
              - DisorderRisk
              - InbreedingRiskProxy
              - MissingDataPenalty
```

本阶段只做单猫繁育价值。配对兼容和近亲检查属于房间规划输入，但可提前提供接口。

配置示例：

```json
{
  "breeding_scoring": {
    "core_breeders_per_sex_or_role": 4,
    "reserve_breeders": 4,
    "minimum_core_score": 0,
    "minimum_reserve_score": 0,
    "stat_weights": {},
    "rare_mutation_weights": {},
    "ability_weights": {},
    "disorder_penalties": {},
    "protect_unknown_rare_traits": true
  },
  "classification": {
    "combat_priority_over_breeding": false,
    "keep_top_combat": 8,
    "keep_top_breeders": 8,
    "minimum_general_reserve": 4,
    "never_cull_if_data_confidence_below": 0.85
  }
}
```

## 淘汰候选生成

只有同时满足以下条件才可进入候选：

1. 不在任何保护集合。
2. 不是高评分战斗猫。
3. 不是核心或备用繁育猫。
4. 超出最低保留数量。
5. 数据置信度高于阈值。
6. 不处于未知特殊状态。
7. 淘汰后仍满足房间/血统/可战斗最低保障。

候选只表示“可以在预览中建议淘汰”，不执行。

## 决策数据结构

```cpp
enum class CatRole {
    CombatRecommended,
    BreedingCore,
    BreedingReserve,
    GeneralReserve,
    CullCandidate,
    ProtectedUnmanaged,
    Ineligible
};

struct CatDecision {
    CatId cat_id;
    CatRole primary_role;
    double combat_score;
    double breeding_score;
    double confidence;
    std::vector<std::string> reasons;
    bool destructive_action_allowed;
};

struct ClassificationPlan {
    uint64_t snapshot_id;
    std::vector<CatDecision> decisions;
    std::vector<std::string> global_warnings;
};
```

## 数量保障

无论分数多低都必须保留：

- 至少 `minimum_combat_pool` 只可出战成年猫。
- 至少 `minimum_breeding_pool` 只可繁育猫，若能识别性别/兼容条件则分别保障。
- 至少 `minimum_general_reserve` 只备用猫。
- 所有受保护猫。

猫数量很少时，候选列表应为空。

## 房间不足的联系

本阶段不根据房间不足直接淘汰，只输出两套候选：

- `quality_cull_candidates`：基于价值低。
- `capacity_relief_candidates`：若第 9 阶段判定空间不足，可从中按优先级选择。

这样避免把房间规划失败误当作“猫差”。

## 测试

- 猫舍只有 1–8 只猫，不得过度淘汰。
- 高战斗低繁育、高繁育低战斗、两者都高、两者都低。
- 数据置信度不足。
- 所有猫被保护。
- 同分稳定排序。
- 大量猫时保持最低池数量。

## 验收标准

- 能生成可解释分类计划。
- 默认不执行任何淘汰。
- 房间容量因素与质量因素分离。
- 不包含自动组队逻辑。
