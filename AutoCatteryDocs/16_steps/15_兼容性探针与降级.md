# 第 15 阶段：游戏版本兼容、MOD 冲突探针与降级路径

## 文档定位

让 MOD 在游戏更新、UI 变化或其他 MOD 冲突时安全降级，而不是误写猫数据。


## 给 Codex 的通用执行规则

1. **只实施本文档对应的阶段**，不得提前实现后续阶段，也不得把多个阶段合并为一次大改动。
2. 开始前先检查当前仓库实际状态、已有提交、构建方式和本阶段依赖是否已完成；已有实现优先复用，不重复造轮子。
3. 允许联网查找与本阶段有关的公开资料来核实事实。本文档和外部资料都只能作为参考；游戏值、接口、偏移、场景与 UI 信息必须以当前仓库、当前游戏 build、本地只读探针或实机证据为准，不得照搬未验证内容或擅自改换技术路线。
4. 不修改游戏原始文件，不提交游戏二进制、反编译产物、个人存档、第三方闭源资产或未经许可的代码。
5. 每个阶段都必须：先读取相关文件 → 做最小修改 → 构建/测试 → 记录结果 → 创建一个本地 Git commit。**绝不自动 push 到 GitHub。**
6. 遇到未知的游戏函数、结构体偏移、场景名或 UI 节点名时，不得编造。应增加探针、日志、适配接口或安全失败路径，并把待确认项写入阶段报告。
7. 任何会移动、淘汰或写入猫数据的功能，默认必须可预览、可取消、可回滚；无法确认安全时只能进入只读模式。
8. 本阶段验收未通过时停止，不继续下一阶段。输出实际改动文件、测试结果、剩余风险和本地 commit 哈希。


## 固定技术基线

- 主路线：Windows x64 原生 DLL MOD。
- 运行时加载器：**Mewjector**。
- 游戏内 UI：**MewUI API**，以源码依赖方式编译进本 MOD。
- 可选安装管理器：Mewtator，仅用于安装和启停，不属于硬依赖。
- 参考实现：
  - Quick-Cleanup：参考“家园场景注入按钮并触发一次性操作”。
  - Mewgenics Breeding Manager：参考猫评分、血缘/近亲检查、房间优化、文件竞态处理；只能复用许可证允许的代码。
  - Online Savegame Editor：参考 `.sav` 解析、SQLite/LZ4、dirty tracking、备份和安全写回。
  - Mewgenics QoL Manager：仅参考批量筛选、房间移动、符号标记的交互思路。
  - MewgenicsModTool：仅作为“实时读取、推荐、cull 可行”的能力证据；未获许可时不得复制代码或资源。
- 不采用“自动组队策略”。战斗猫只按独立评分排序和标记，不分析职业搭配、站位或队伍协同。
- 两个主动按钮：
  1. 家园界面：`自动整理猫舍`。只有玩家点击后才分析、分类、淘汰和调整房间。
  2. 次日出征/选猫界面：`标记推荐战斗猫`。点击后只高亮高评分猫，不自动选队。

## Build 指纹

组合使用：

- 游戏可执行文件版本信息。
- 文件大小/时间仅作辅助。
- 关键模块或只读代码段哈希。
- 已验证结构签名版本。
- Mewjector/MewUI API 版本。

```cpp
struct BuildFingerprint {
    std::string executable_version;
    std::string text_hash;
    std::string data_signature_version;
    std::string ui_signature_version;
};
```

## 兼容级别

```cpp
enum class CompatibilityLevel {
    VerifiedFull,
    VerifiedReadOnly,
    UnknownReadOnly,
    IncompatibleDisabled
};
```

- `VerifiedFull`：评分、移动、淘汰、标记均可。
- `VerifiedReadOnly`：只分析和标记，不移动/淘汰。
- `UnknownReadOnly`：只显示诊断，标记也需重新映射成功。
- `IncompatibleDisabled`：完全不注入按钮或只显示错误入口。

## 结构探针

启动时和第一次点击前验证：

- 猫列表容器可读。
- ID 唯一率。
- 房间引用一致。
- 关键字段范围。
- UI 节点模板签名。
- 写接口指向已知函数/对象。

探针不得通过写入真实猫来验证。写能力验证使用专用测试存档和显式开发模式。

## MOD 冲突

检测可能修改相同区域的已加载 DLL 或 UI 唯一节点：

- 若另一个 MOD 已创建相同 ID，停止注入。
- 若 Quick-Cleanup 等只在同一按钮组添加节点，应动态布局，不视为冲突。
- 若检测到其他自动移动/淘汰工具，默认禁止执行并提示用户选择一个。
- 不卸载、不篡改其他 MOD。

建立 `compatibility_overrides.json`，允许已验证组合，但未知组合仍保守。

## 运行时健康检查

每次按钮点击前快速检查；不要每帧扫描。发现结构变化时立即把当前会话降级为只读，清除高亮并取消待执行预览。

## 诊断包

用户可手动导出：

- build 指纹。
- MOD 列表和版本。
- 场景签名摘要。
- capability matrix。
- 最近错误日志。
- 不包含存档、猫名和个人路径。

## 版本适配注册表

```cpp
class AdapterRegistry {
public:
    Result<std::unique_ptr<IGameReadAdapter>> CreateReadAdapter(const BuildFingerprint&);
    Result<std::unique_ptr<IGameWriteAdapter>> CreateWriteAdapter(const BuildFingerprint&);
};
```

不同 build 的偏移/签名隔离在独立适配器目录，禁止散落在业务代码。

## 测试

- 已知完整 build。
- 已知只读 build。
- 未知 build。
- UI 结构改变。
- 猫字段偏移错位导致异常值。
- 同名按钮冲突。
- 其他 DLL 加载顺序变化。

## 验收标准

- 未知 build 默认不执行写操作。
- 冲突不会导致重复按钮或双重淘汰。
- 诊断包可用于后续适配但不泄露存档。
- 所有业务模块只通过 AdapterRegistry 获取适配器。
