# 第 14 阶段：存档安全、原子写入与恢复工具

## 文档定位

强化存档级安全。如果运行时操作已经完全由游戏 API 安全持久化，本阶段仍要提供外部备份和恢复验证；若需要直接写 `.sav`，必须严格事务化。


## 给 Codex 的通用执行规则

1. **只实施本文档对应的阶段**，不得提前实现后续阶段，也不得把多个阶段合并为一次大改动。
2. 开始前先检查当前仓库实际状态、已有提交、构建方式和本阶段依赖是否已完成；已有实现优先复用，不重复造轮子。
3. 不进行新的联网研究，不搜索新的 MOD，不擅自改换技术路线。本文档中的外部项目只作为既定参考基线。
4. 不修改游戏原始文件，不提交游戏二进制、反编译产物、个人存档、第三方闭源资产或未经许可的代码。
5. 每个阶段都必须：先读取相关文件 → 做最小修改 → 构建/测试 → 记录结果 → 创建一个本地 Git commit。**绝不自动 push 到 GitHub。**
6. 遇到未知的游戏函数、结构体偏移、场景名或 UI 节点名时，不得编造。应增加探针、日志、适配接口或安全失败路径，并把待确认项写入阶段报告。
7. 任何会移动、淘汰或写入猫数据的功能，默认必须可预览、可取消、可回滚；无法确认安全时只能进入只读模式。
8. 本阶段验收未通过时停止，不继续下一阶段。输出实际改动文件、测试结果、剩余风险和本地 commit 哈希。


## 固定技术基线

- 主路线：Windows x64 原生 DLL MOD。
- 运行时加载器：**Mewjector**。
- 游戏内 UI：**MewUI API**，以源码依赖方式编译进本 MOD。
- 可选安装管理器：Mewtator，仅用于安装和启停，不属于硬依赖。
- 参考实现：
  - Quick-Cleanup：参考“家园场景注入按钮并触发一次性操作”。
  - Mewgenics Breeding Manager：参考猫评分、血缘/近亲检查、房间优化、文件竞态处理；只能复用许可证允许的代码。
  - Online Savegame Editor：参考 `.sav` 解析、SQLite/LZ4、dirty tracking、备份和安全写回。
  - Mewgenics QoL Manager：仅参考批量筛选、房间移动、符号标记的交互思路。
  - MewgenicsModTool：仅作为“实时读取、推荐、cull 可行”的能力证据；未获许可时不得复制代码或资源。
- 不采用“自动组队策略”。战斗猫只按独立评分排序和标记，不分析职业搭配、站位或队伍协同。
- 两个主动按钮：
  1. 家园界面：`自动整理猫舍`。只有玩家点击后才分析、分类、淘汰和调整房间。
  2. 次日出征/选猫界面：`标记推荐战斗猫`。点击后只高亮高评分猫，不自动选队。

## 原则

优先使用游戏自身运行时对象和正常保存流程。直接编辑 `.sav` 只能作为明确验证过的适配器或恢复方案，不能边运行边盲写。

研究基线表明可参考 SQLite + LZ4 blob、dirty tracking 和 `.savbak`；实际字段、表名和压缩块必须由本地适配器验证，禁止照猜。

## SaveAdapter 分层

```cpp
class ISaveBackupService {
public:
    virtual Result<BackupInfo> CreateBackup(std::string_view operation_id) = 0;
    virtual Result<void> VerifyBackup(const BackupInfo&) = 0;
    virtual Result<void> RestoreBackup(const BackupInfo&) = 0;
};

class IDirectSaveEditor {
public:
    virtual Result<ParsedSave> ParseReadOnly(const path&) = 0;
    virtual Result<void> ApplyDirtyBlocksAtomically(const ParsedSave&, const path&) = 0;
};
```

默认构建可以只实现 `ISaveBackupService`，把直接写编辑器放在 feature flag 后。

## 备份目录

```text
AutoCatteryData/
└─ backups/
   └─ <save-slot>/
      └─ <timestamp>_<operation-id>/
         ├─ original.savbak
         ├─ manifest.json
         ├─ operation-journal.json
         └─ verification.txt
```

manifest 包含文件大小、SHA-256、游戏 build、mod version、game day、原路径的脱敏标识。

## 文件锁与稳定窗口

备份前：

1. 检测文件存在。
2. 连续两次读取大小和修改时间，间隔 100–250ms，确认稳定。
3. 尝试共享读取或平台文件锁。
4. 游戏报告保存中则等待短暂窗口；超时取消操作，不无限等待。

## 原子写入

若必须直接写：

1. 只读解析原文件。
2. 在内存中修改 dirty blocks。
3. 写到同卷临时文件。
4. flush 文件和目录元数据。
5. 重新解析临时文件并做结构/引用校验。
6. 原文件重命名为备份。
7. 临时文件原子替换。
8. 再次验证。

Windows 下考虑杀毒软件、云同步和 Steam Cloud 占用。失败时保留临时文件和原备份，不删除证据。

## 恢复工具

提供命令行或 PowerShell：

```powershell
Restore-AutoCatteryBackup.ps1 -List
Restore-AutoCatteryBackup.ps1 -OperationId <id> -VerifyOnly
Restore-AutoCatteryBackup.ps1 -OperationId <id> -Restore
```

恢复前要求游戏关闭或明确检测不到进程；恢复当前存档前再备份一次损坏文件。

## Steam Cloud

不试图控制 Steam Cloud。文档提示恢复后可能发生云冲突，用户应选择正确的本地/云版本。MOD 日志记录但不自动删除云文件。

## 保留策略

默认最近 20 次或 30 天。删除旧备份前必须确保至少保留最后一次成功整理前备份和最后一次手动恢复前备份。

## 测试

- 文件正在写入。
- 无权限、磁盘满、跨卷路径。
- 临时文件验证失败。
- LZ4/SQLite 解析错误。
- 恢复时游戏仍运行。
- Steam Cloud 模拟外部修改。
- 备份目录中有损坏 manifest。

## 验收标准

- 每次淘汰前有可验证备份。
- 恢复工具能列出、校验和恢复测试副本。
- 直接写功能默认关闭，除非适配器测试全部通过。
- 不在游戏保存窗口强行写文件。
