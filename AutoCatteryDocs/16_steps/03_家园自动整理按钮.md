# 第 03 阶段：家园“自动整理猫舍”按钮最小实现

## 文档定位

在家园界面加入按钮，但本阶段点击后只执行安全检查和占位预览，不读取、移动或淘汰猫。

## 固定技术基线

- 主路线：Windows x64 原生 DLL MOD。
- 运行时加载器：**Mewjector**。
- 游戏内 UI：**MewUI API**，以源码依赖方式编译进本 MOD。
- 可选安装管理器：Mewtator，仅用于安装和启停，不属于硬依赖。
- 参考实现：
  - Quick-Cleanup：参考“家园场景注入按钮并触发一次性操作”。
  - Mewgenics Breeding Manager：参考猫评分、血缘/近亲检查、房间优化、文件竞态处理；只能复用许可证允许的代码。
  - Online Savegame Editor：参考 `.sav` 解析、SQLite/LZ4、dirty tracking、备份和安全写回。
  - Mewgenics QoL Manager：仅参考批量筛选、房间移动、符号标记的交互思路。
  - MewgenicsModTool：仅作为“实时读取、推荐、cull 可行”的能力证据；未获许可时不得复制代码或资源。
- 不采用“自动组队策略”。战斗猫只按独立评分排序和标记，不分析职业搭配、站位或队伍协同。
- 两个主动按钮：
  1. 家园界面：`自动整理猫舍`。只有玩家点击后才分析、分类、淘汰和调整房间。
  2. 次日出征/选猫界面：`标记推荐战斗猫`。点击后只高亮高评分猫，不自动选队。

## 目标交互

- 仅在 `HouseReady` 显示。
- 文案：`自动整理猫舍`。
- 点击后弹出占位面板，显示“功能尚未接入数据层”。
- 离开家园立即移除按钮。
- 重复进入场景不能产生重复按钮。

## UI 注入策略

优先参考 Quick-Cleanup 的方式：复制或创建一个符合原游戏视觉的现有按钮节点，再替换文本和点击回调。不要修改原按钮事件，不覆盖原节点 ID。

建立唯一标识：

```text
AutoCattery.House.AutoOrganizeButton
```

注入流程：

1. 收到 `HouseReady`。
2. 延迟到 UI 稳定帧。
3. 查找预设锚点或可复制按钮模板。
4. 若唯一按钮已存在，只刷新状态，不重复创建。
5. 注册点击事件。
6. 在场景卸载前注销事件并销毁自建节点。

## 按钮状态

```cpp
enum class OrganizeButtonState {
    Hidden,
    DisabledUnsupportedBuild,
    DisabledBusy,
    Ready,
    Running,
    Completed,
    Failed
};
```

文案建议：

- Ready：`自动整理猫舍`
- Running：`正在分析…`
- Completed：`整理完成`
- Unsupported：`当前版本仅可预览`

本阶段只有 Ready 和占位 Completed/Failed。

## 防误触

- 点击后 500ms 内去抖。
- 运行中忽略重复点击。
- 不在暂停、保存、场景切换时响应。
- 本阶段弹窗必须明确写“没有修改任何猫”。

## UI 布局回退

从高到低：

1. 放在家园现有管理按钮组末尾。
2. 放在屏幕边缘的独立小面板。
3. 若无法安全注入，禁用按钮并只记日志；不得覆盖原 UI。

分辨率测试：1280×720、1920×1080、2560×1440、超宽屏；UI 缩放 80%–150%。

## 测试与验收

- 家园进入/退出 10 次，始终只有一个按钮。
- 点击 20 次无事件重复、无泄漏。
- 点击时不会触发原有相邻按钮。
- 保存、暂停、切场景时按钮自动禁用。
- 日志记录 attach/detach/click，但不每帧刷屏。
- 没有任何猫或存档数据发生变化。
