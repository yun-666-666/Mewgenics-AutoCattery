# 第 05 阶段：猫、房间与运行时数据快照

## 文档定位

建立只读数据适配层，把游戏中的猫和房间转换为稳定的领域模型。不得写入。


## 给 Codex 的通用执行规则

1. **只实施本文档对应的阶段**，不得提前实现后续阶段，也不得把多个阶段合并为一次大改动。
2. 开始前先检查当前仓库实际状态、已有提交、构建方式和本阶段依赖是否已完成；已有实现优先复用，不重复造轮子。
3. 不进行新的联网研究，不搜索新的 MOD，不擅自改换技术路线。本文档中的外部项目只作为既定参考基线。
4. 不修改游戏原始文件，不提交游戏二进制、反编译产物、个人存档、第三方闭源资产或未经许可的代码。
5. 每个阶段都必须：先读取相关文件 → 做最小修改 → 构建/测试 → 记录结果 → 创建一个本地 Git commit。**绝不自动 push 到 GitHub。**
6. 遇到未知的游戏函数、结构体偏移、场景名或 UI 节点名时，不得编造。应增加探针、日志、适配接口或安全失败路径，并把待确认项写入阶段报告。
7. 任何会移动、淘汰或写入猫数据的功能，默认必须可预览、可取消、可回滚；无法确认安全时只能进入只读模式。
8. 本阶段验收未通过时停止，不继续下一阶段。输出实际改动文件、测试结果、剩余风险和本地 commit 哈希。


## 固定技术基线

- 主路线：Windows x64 原生 DLL MOD。
- 运行时加载器：**Mewjector**。
- 游戏内 UI：**MewUI API**，以源码依赖方式编译进本 MOD。
- 可选安装管理器：Mewtator，仅用于安装和启停，不属于硬依赖。
- 参考实现：
  - Quick-Cleanup：参考“家园场景注入按钮并触发一次性操作”。
  - Mewgenics Breeding Manager：参考猫评分、血缘/近亲检查、房间优化、文件竞态处理；只能复用许可证允许的代码。
  - Online Savegame Editor：参考 `.sav` 解析、SQLite/LZ4、dirty tracking、备份和安全写回。
  - Mewgenics QoL Manager：仅参考批量筛选、房间移动、符号标记的交互思路。
  - MewgenicsModTool：仅作为“实时读取、推荐、cull 可行”的能力证据；未获许可时不得复制代码或资源。
- 不采用“自动组队策略”。战斗猫只按独立评分排序和标记，不分析职业搭配、站位或队伍协同。
- 两个主动按钮：
  1. 家园界面：`自动整理猫舍`。只有玩家点击后才分析、分类、淘汰和调整房间。
  2. 次日出征/选猫界面：`标记推荐战斗猫`。点击后只高亮高评分猫，不自动选队。

## 核心原则

- 游戏内对象只在适配器层出现。
- 评分、分类和房间规划只使用不可变快照。
- 未确认字段标记为 Unknown，不以 0 代替。
- 每次点击工作流重新拍摄快照，不做长期轮询。

## 猫模型

```cpp
using CatId = uint64_t;
using RoomId = uint64_t;

enum class TriState { Unknown, No, Yes };

enum class LifeStage { Unknown, Kitten, Adult, Senior, Dead };

struct StatBlock {
    std::optional<int> strength;
    std::optional<int> dexterity;
    std::optional<int> constitution;
    std::optional<int> intelligence;
    std::optional<int> speed;
    std::optional<int> luck;
};

struct CatSnapshot {
    CatId id;
    std::string display_name;
    LifeStage life_stage;
    int age_days{-1};
    StatBlock base_stats;
    StatBlock current_stats;
    std::string class_id;
    std::vector<std::string> abilities;
    std::vector<std::string> passives;
    std::vector<std::string> mutations;
    std::vector<std::string> disorders;
    std::vector<CatId> parents;
    std::vector<CatId> children;
    RoomId room_id{};
    TriState injured{TriState::Unknown};
    TriState available_for_combat{TriState::Unknown};
    TriState available_for_breeding{TriState::Unknown};
    TriState player_favorite{TriState::Unknown};
    TriState game_locked{TriState::Unknown};
    uint64_t raw_revision{};
};
```

## 房间模型

```cpp
struct RoomSnapshot {
    RoomId id;
    std::string room_type;
    std::vector<CatId> residents;
    std::optional<int> hard_capacity;
    int soft_capacity{4};
    std::optional<int> comfort;
    std::optional<int> stimulation;
    bool allows_breeding{false};
    bool allows_kittens{true};
    bool is_special_room{false};
    bool player_locked{false};
};

struct HouseSnapshot {
    uint64_t snapshot_id;
    uint64_t scene_generation;
    int game_day{-1};
    std::string game_build_id;
    std::vector<CatSnapshot> cats;
    std::vector<RoomSnapshot> rooms;
    std::chrono::system_clock::time_point captured_at;
};
```

## 稳定 ID

必须找到游戏内稳定的猫 ID；名字不能作为 ID。若只发现运行时指针：

1. 尝试映射存档主键或内部 GUID。
2. 找不到稳定 ID 时，阶段只能输出诊断，禁止进入写阶段。
3. 指针仅作为当前快照内的 `runtime_handle`，不能持久化到次日。

## 适配器接口

```cpp
class IGameReadAdapter {
public:
    virtual ~IGameReadAdapter() = default;
    virtual Result<HouseSnapshot> CaptureHouseSnapshot() = 0;
    virtual Result<std::vector<CatSnapshot>> CaptureEmbarkCandidates() = 0;
    virtual Result<int> CurrentGameDay() = 0;
    virtual bool IsSaveInProgress() const = 0;

```

## 数据验证

拍摄完成后执行：

- 猫 ID 唯一。
- 房间 ID 唯一。
- 每只猫最多属于一个房间。
- 房间 residents 中的猫必须存在。
- 父母/子女引用不存在时保留 ID 并记录 orphan warning。
- 数值超出合理范围时不修正，只标记异常。
- 死猫、战斗中猫、临时 NPC 猫分别标记，避免进入普通管理集合。

## 字段能力表

建立 `CapabilityMatrix`：

```cpp
struct CapabilityMatrix {
    bool stable_cat_id;
    bool read_base_stats;
    bool read_abilities;
    bool read_relationships;
    bool read_room_assignments;
    bool read_favorite_flag;
    bool read_lock_flag;
    bool read_combat_eligibility;
};
```

后续评分器依据能力表选择降级算法；缺少稳定 ID 或房间数据时，禁止自动移动/淘汰。

## 诊断输出

只输出脱敏摘要：猫数量、房间数量、字段可用率、异常计数。可选生成本地 fixture，但默认去除名字并散列 ID。

## 测试

- 空猫舍。
- 1 只猫、1 房间。
- 100/500/1000 只猫。
- 重复 ID、丢失房间、孤儿关系。
- 字段全部 Unknown。
- 场景切换中拍摄应失败而不是返回半快照。

## 验收标准

- 在家园按钮点击占位流程中能生成只读快照摘要。
- 连续拍摄相同状态时稳定 ID 不变。
- 不写任何数据。
- 不持有场景销毁后的原始指针。
