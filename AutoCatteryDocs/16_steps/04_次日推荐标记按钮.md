# 第 04 阶段：验证次日界面并实现“标记推荐战斗猫”按钮

## 文档定位

本阶段必须先用真实运行证据确认玩家所指界面、内部场景状态、UI 挂载点和可控的显示/隐藏方式，然后才能实现推荐按钮。

玩家确认的目标画面是：**新一天开始后、仍能看到家园且右侧存在游戏原生“出发!”牌子的画面**。玩家截图是视觉含义的基准。`House`、`ClassChooser`、`EmbarkSelectionReady` 等内部名称不能代替画面验证，也不能仅凭名称决定按钮挂载位置。

本阶段仍不读取真实猫评分，不自动选择猫，不修改猫、房间或存档。

玩家在 2026-07-28 进一步确认：推荐按钮只在每天第一次出征前的新一天 House 显示；当天战斗归来后不再显示，直到结束当天并进入下一天才再次出现。阶段 03 按钮在新一天和战斗归来后的正常 House 都显示。玩家随后明确取消家具模式问题的修复与验收要求，本阶段不再改动或评判家具模式中的阶段 03 按钮。

1. 在玩家确认的“新一天＋出发牌”目标画面显示一个稳定、可点击的“标记推荐战斗猫”按钮。

阶段 03 与阶段 04 两个 MOD 按钮必须缩小后横向并排放在右上角资源栏

## A. 证据阶段：先映射真实界面

### A1. 建立基线

在任何正式 UI 修改前，使用当前阶段 03 基线记录：

- 新一天目标画面的截图和时间。
- 当天第一次战斗归来后的 House 截图和时间。
- 点击游戏原生“出发!”牌子前后的截图和时间。
- 同一时段 AutoCattery 的 `SceneContext`、`SceneProbe` 日志。
- 对应的场景 generation、加载场景摘要和可交互状态。

存档选择和游戏内导航由玩家操作。Codex 不得替玩家选择存档或推进游戏。

### A2. 验证目标画面含义

必须用同一时间窗口的截图与日志回答：

- 玩家目标画面出现时，当前内部 context 是什么？
- 哪个可靠只读信号能区分当天首次出征前与战斗归来后的 House？
- `House` 与 `ClassChooser` 分别在玩家哪一个可见画面出现？
- 点击“出发!”前后，context、generation 和加载场景怎样变化？

如果现有日志不能回答，只能增加最小只读探针。探针可以记录稳定标识、父子路径、组件类型、可见/交互状态和生命周期，但不得导出纹理、脚本、完整游戏资产或个人存档。

### A3. 验证挂载与可见性能力

正式实现前必须分别证明：

- 目标画面存在一个由当前 MewUI API 可安全访问、生命周期明确的挂载点。
- 自建控件可以只影响 MOD 自己的节点。
- 当前 API 存在已验证的隐藏/移除方法，且不会让 MovieClip 自动播放、闪烁或暴露其他帧。
- 离开目标画面或 generation 改变时，可以先清理自建节点再释放引用。

“找到字符串”“单元测试能模拟”“SWF 可重复生成”均不等于上述能力已在游戏中证明。

## 证据门禁

只有同时具备以下证据，才允许进入正式实现：

- 玩家截图与日志已经一一对应。
- 目标画面的真实 context 已确认。
- 每日首次出征前/战斗归来后的状态信号已确认，且不依赖猜测日期或存档字段。
- 目标挂载点已在真实运行时读到，并记录稳定识别方式和生命周期。
- 显示、隐藏或移除方式已经通过最小现场实验验证无闪烁、无残留。
- 未复用 House 测试节点去访问另一个场景。

任何一项缺失时：

1. 停止 UI 实现。
2. 保留安全的只读探针和证据。
3. 在阶段报告中写明阻塞项和下一次需要玩家执行的最小操作。
4. 不得把阶段状态写成完成。

## B. 实现阶段：仅在门禁通过后执行

### B1. 推荐按钮

- 只显示在玩家确认的目标画面。
- 只在每天第一次出征前显示；当天战斗归来后保持不显示，下一天重新显示。
- 唯一角色标识：`AutoCattery.Recommendation.MarkCombatCatsButton`。
- 文案：`标记推荐战斗猫`。
- 第一次点击显示纯演示标记，第二次点击清除。
- 演示标记只能附着于 MOD 自己创建并验证的安全节点，不得把任意真实猫标成推荐对象。
- 当前阶段只需一种稳定、清晰的视觉形式；不得为追求三层动画而引入未经验证的时间轴或脉冲效果。
- 按钮和标记必须绑定 `scene_generation`，generation 改变时先清理再卸载。

### B2. 家具模式

- 玩家已取消该问题的修复与验收要求。
- 本阶段不新增家具模式逻辑，也不把当前家具模式表现作为完成阻塞项。

### B3. 安全边界

- 不改变游戏原生“出发!”牌子。
- 不改变任何选猫状态。
- 不调用真实评分、猫、房间、队伍、休息、日期推进或存档接口。
- UI 不直接访问游戏状态写接口。

## 游戏内验收

### 新一天目标画面

- 游戏原生“出发!”牌子保持原样。
- 只出现预期的 MOD 控件。
- 两个 MOD 按钮在右上角资源栏下方横向并排，且不遮挡任何原生牌子。
- 推荐按钮稳定、可点击、无闪烁。
- 不出现示例文字、计数器、导航控件或后备演示画面。

### 交互与安全

- 推荐按钮切换五十次，不改变选猫状态。
- 目标画面往返十次，无重复按钮和残留节点。
- 分辨率至少覆盖 1280×720、1920×1080、2560×1440 和一种超宽屏；UI 缩放覆盖 80%–150%。
- 不读取或修改猫、房间、存档、日期和出征选择。
- 最新日志没有重复挂载错误。
