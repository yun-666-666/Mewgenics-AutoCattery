# 第 11 阶段：家园按钮完整自动整理流水线

## 文档定位

把快照、评分、分类、保护、房间规划和执行整合到“自动整理猫舍”按钮，但仍保持预览和明确触发。


## 给 Codex 的通用执行规则

1. **只实施本文档对应的阶段**，不得提前实现后续阶段，也不得把多个阶段合并为一次大改动。
2. 开始前先检查当前仓库实际状态、已有提交、构建方式和本阶段依赖是否已完成；已有实现优先复用，不重复造轮子。
3. 允许联网查找与本阶段有关的公开资料来核实事实。本文档和外部资料都只能作为参考；游戏值、接口、偏移、场景与 UI 信息必须以当前仓库、当前游戏 build、本地只读探针或实机证据为准，不得照搬未验证内容或擅自改换技术路线。
4. 不修改游戏原始文件，不提交游戏二进制、反编译产物、个人存档、第三方闭源资产或未经许可的代码。
5. 每个阶段都必须：先读取相关文件 → 做最小修改 → 构建/测试 → 记录结果 → 创建一个本地 Git commit。**绝不自动 push 到 GitHub。**
6. 遇到未知的游戏函数、结构体偏移、场景名或 UI 节点名时，不得编造。应增加探针、日志、适配接口或安全失败路径，并把待确认项写入阶段报告。
7. 任何会移动、淘汰或写入猫数据的功能，默认必须可预览、可取消、可回滚；无法确认安全时只能进入只读模式。
8. 本阶段验收未通过时停止，不继续下一阶段。输出实际改动文件、测试结果、剩余风险和本地 commit 哈希。


## 固定技术基线

- 主路线：Windows x64 原生 DLL MOD。
- 运行时加载器：**Mewjector**。
- 游戏内 UI：**MewUI API**，以源码依赖方式编译进本 MOD。
- 可选安装管理器：Mewtator，仅用于安装和启停，不属于硬依赖。
- 参考实现：
  - Quick-Cleanup：参考“家园场景注入按钮并触发一次性操作”。
  - Mewgenics Breeding Manager：参考猫评分、血缘/近亲检查、房间优化、文件竞态处理；只能复用许可证允许的代码。
  - Online Savegame Editor：参考 `.sav` 解析、SQLite/LZ4、dirty tracking、备份和安全写回。
  - Mewgenics QoL Manager：仅参考批量筛选、房间移动、符号标记的交互思路。
  - MewgenicsModTool：仅作为“实时读取、推荐、cull 可行”的能力证据；未获许可时不得复制代码或资源。
- 不采用“自动组队策略”。战斗猫只按独立评分排序和标记，不分析职业搭配、站位或队伍协同。
- 两个主动按钮：
  1. 家园界面：`自动整理猫舍`。只有玩家点击后才分析、分类、淘汰和调整房间。
  2. 次日出征/选猫界面：`标记推荐战斗猫`。点击后只高亮高评分猫，不自动选队。

## 最终按钮流程

```text
玩家在家园点击“自动整理猫舍”
 → 安全状态检查
 → 拍摄快照
 → 战斗评分
 → 繁育评分
 → 分类
 → 保护过滤
 → 房间规划
 → 生成预览
 → 玩家确认执行（默认）
 → 备份
 → 移动
 → 淘汰
 → 校验
 → 保存推荐快照
 → 显示结果
```

只有按钮点击才执行，禁止后台自动整理、回家自动触发或定时触发。

## 应用服务

```cpp
class OrganizeCatteryWorkflow {
public:
    Result<OrganizePreview> BuildPreview();
    Result<OrganizeOutcome> Execute(const std::string& preview_id);
    Result<void> Cancel(const std::string& preview_id);
};
```

预览具有短期有效期和 scene generation 绑定。

## 预览内容

- 猫总数、房间总数。
- 推荐战斗猫数量和排名摘要。
- 核心/备用繁育猫数量。
- 计划移动数量。
- 计划淘汰数量。
- 保护猫数量。
- 房间不足、数据缺失、兼容模式警告。
- 详细可展开列表。

按钮：

- `执行整理`
- `仅移动，不淘汰`
- `取消`
- `导出报告`

如果当前无破坏性操作，可直接显示完成，不要求二次确认。

## 推荐快照保存

整理成功后写 MOD sidecar：

```json
{
  "schema_version": 1,
  "created_on_game_day": 120,
  "source_snapshot_id": 8891,
  "combat_algorithm_version": "1",
  "config_hash": "...",
  "recommended": [
    {"cat_id": "123", "rank": 1, "score": 92.4, "confidence": 1.0}
  ]
}
```

该文件不直接修改游戏；供第 12 阶段次日按钮使用。

## 幂等性

同一天在无状态变化时再次点击：

- 快照哈希相同则复用评分。
- 房间已经符合计划时 moves 为 0。
- 已淘汰猫不再出现。
- 仍可重新生成预览，但不得重复执行同一 preview ID。

## 房间不足提示

结果必须明确区分：

- `完全整理成功`
- `部分成功：N 只猫保持原房间`
- `容量不足：建议增加房间或允许淘汰 M 只候选`
- `只读模式：已完成分析但未修改`

禁止只显示“成功”而隐藏未安置猫。

## 性能目标

- 100 只猫预览目标 < 250ms（不含 UI 动画）。
- 1000 只猫目标 < 2s。
- 不每帧扫描全部猫。
- 进度超过 100ms 才显示进度动画，避免闪烁。

## 异常处理

任何模块异常统一映射为用户可理解结果，详细堆栈写日志。工作流对象使用 RAII 清理临时状态；失败后按钮恢复 Ready。

## 测试

- 空猫舍。
- 无需移动/淘汰。
- 仅移动。
- 仅淘汰。
- 房间不足部分成功。
- 用户取消。
- 预览过期。
- 整理过程中切场景。
- 同日重复整理。
- 推荐快照写入失败：整理可成功，但提示次日推荐不可用。

## 验收标准

- 没点击按钮时完全不整理。
- 点击后可以完成预览和明确执行。
- 结果报告准确。
- 整理成功后生成推荐快照。
- 不自动休息或进入下一天。
