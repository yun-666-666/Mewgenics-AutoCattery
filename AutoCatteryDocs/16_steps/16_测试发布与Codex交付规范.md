# 第 16 阶段：测试、发布清单与 Codex 分步交付规范

## 文档定位

完成系统测试、性能验证、恢复演练、安装包和发布文档，并规定 Codex 每次如何安全交付。


## 给 Codex 的通用执行规则

1. **只实施本文档对应的阶段**，不得提前实现后续阶段，也不得把多个阶段合并为一次大改动。
2. 开始前先检查当前仓库实际状态、已有提交、构建方式和本阶段依赖是否已完成；已有实现优先复用，不重复造轮子。
3. 不进行新的联网研究，不搜索新的 MOD，不擅自改换技术路线。本文档中的外部项目只作为既定参考基线。
4. 不修改游戏原始文件，不提交游戏二进制、反编译产物、个人存档、第三方闭源资产或未经许可的代码。
5. 每个阶段都必须：先读取相关文件 → 做最小修改 → 构建/测试 → 记录结果 → 创建一个本地 Git commit。**绝不自动 push 到 GitHub。**
6. 遇到未知的游戏函数、结构体偏移、场景名或 UI 节点名时，不得编造。应增加探针、日志、适配接口或安全失败路径，并把待确认项写入阶段报告。
7. 任何会移动、淘汰或写入猫数据的功能，默认必须可预览、可取消、可回滚；无法确认安全时只能进入只读模式。
8. 本阶段验收未通过时停止，不继续下一阶段。输出实际改动文件、测试结果、剩余风险和本地 commit 哈希。


## 固定技术基线

- 主路线：Windows x64 原生 DLL MOD。
- 运行时加载器：**Mewjector**。
- 游戏内 UI：**MewUI API**，以源码依赖方式编译进本 MOD。
- 可选安装管理器：Mewtator，仅用于安装和启停，不属于硬依赖。
- 参考实现：
  - Quick-Cleanup：参考“家园场景注入按钮并触发一次性操作”。
  - Mewgenics Breeding Manager：参考猫评分、血缘/近亲检查、房间优化、文件竞态处理；只能复用许可证允许的代码。
  - Online Savegame Editor：参考 `.sav` 解析、SQLite/LZ4、dirty tracking、备份和安全写回。
  - Mewgenics QoL Manager：仅参考批量筛选、房间移动、符号标记的交互思路。
  - MewgenicsModTool：仅作为“实时读取、推荐、cull 可行”的能力证据；未获许可时不得复制代码或资源。
- 不采用“自动组队策略”。战斗猫只按独立评分排序和标记，不分析职业搭配、站位或队伍协同。
- 两个主动按钮：
  1. 家园界面：`自动整理猫舍`。只有玩家点击后才分析、分类、淘汰和调整房间。
  2. 次日出征/选猫界面：`标记推荐战斗猫`。点击后只高亮高评分猫，不自动选队。

## 测试层级

### 单元测试

- 配置解析/迁移。
- 战斗评分、繁育评分。
- 分类和最低池保障。
- 保护优先级。
- 房间规划及回退。
- 计划哈希、journal、备份 manifest。

### 组件测试

- 假游戏适配器。
- 假 UI 树。
- 失败注入写适配器。
- 虚拟列表卡片复用。

### 集成测试

- 家园按钮 → 预览。
- 预览 → 执行 → 校验。
- 手动休息 → 次日按钮 → 高亮。
- 房间不足部分成功。
- 备份 → 故障 → 恢复。

### 游戏内人工测试

必须使用复制的测试存档，按以下顺序：

1. 只读分析。
2. 标记 UI。
3. 移动 1 只测试猫。
4. 回滚移动。
5. 淘汰 1 只明确测试猫。
6. 恢复备份。
7. 10–20 只猫完整整理。
8. 大猫舍和房间不足。
9. 连续多个游戏日。

## 关键验收场景

1. 玩家不点击按钮：零自动整理。
2. 点击家园按钮：生成准确预览。
3. 取消：零修改。
4. 执行：保护猫不动、不淘汰。
5. 房间少：使用软溢出/最少容量释放/部分成功，不崩溃。
6. 繁育房少：只安排可容纳的最高分有效配对，其余备用。
7. 幼猫多：优先安全安置，无法理想分配则报告。
8. 休息后：按钮按需标记高评分战斗猫。
9. 标记不改变选队。
10. 游戏更新：自动只读或禁用。
11. 执行中保存/切场景：取消并回滚。
12. 备份恢复成功。

## 性能与稳定性

- 1000 只猫评分/规划基准。
- 内存增长测试：进出场景 100 次。
- 按钮开关标记 500 次。
- 连续运行 20 个游戏日。
- 日志文件滚动，不无限增长。

## 版本号

使用 SemVer：

- Patch：不改数据模型/规则语义的修复。
- Minor：新增配置、标记样式、兼容 build。
- Major：推荐快照 schema、存档写入或分类语义不兼容变化。

同时记录 `supported_game_builds`。

## Codex 工作量限制

- 一次只处理一个阶段文档。
- 单次最多修改一个逻辑模块和直接相关测试。
- 发现前置缺失时，只修复前置的最小阻塞问题并记录，不顺便实现后续功能。
- 不进行大规模重构，除非本阶段无法安全完成，并在提交中单独说明。
- 每次构建失败先修复当前改动，不通过删除测试或降低安全约束“解决”。

## 最终发布门禁

发布前必须全部满足：

- 已知支持 build 的 Full 测试通过。
- 未知 build 自动只读。
- 保护规则不可绕过。
- 无备份不淘汰。
- 房间不足回退测试通过。
- 次日标记不自动选队。
- 恢复演练成功。
- 第三方许可证清单完成。
- Release DLL 不含调试偏移转储和个人路径。

## 项目完成定义

玩家能够在战斗回家后主动点击一次按钮，安全地完成猫的分析、战斗/繁育分类、低价值候选淘汰和房间调整；玩家手动休息后，在次日出战选择界面主动点击另一个按钮，清晰看到高评分战斗猫标记，同时 MOD 从不自动休息、从不自动选队，并在房间不足、版本未知和写入失败时安全降级。
