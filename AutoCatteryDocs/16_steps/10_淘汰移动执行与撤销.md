# 第 10 阶段：淘汰/移动执行器、备份与撤销包

## 文档定位

首次实现破坏性操作。必须以预览计划为输入，支持备份、并发检查、部分回滚和完整审计。


## 给 Codex 的通用执行规则

1. **只实施本文档对应的阶段**，不得提前实现后续阶段，也不得把多个阶段合并为一次大改动。
2. 开始前先检查当前仓库实际状态、已有提交、构建方式和本阶段依赖是否已完成；已有实现优先复用，不重复造轮子。
3. 允许联网查找与本阶段有关的公开资料来核实事实。本文档和外部资料都只能作为参考；游戏值、接口、偏移、场景与 UI 信息必须以当前仓库、当前游戏 build、本地只读探针或实机证据为准，不得照搬未验证内容或擅自改换技术路线。
4. 不修改游戏原始文件，不提交游戏二进制、反编译产物、个人存档、第三方闭源资产或未经许可的代码。
5. 每个阶段都必须：先读取相关文件 → 做最小修改 → 构建/测试 → 记录结果 → 创建一个本地 Git commit。**绝不自动 push 到 GitHub。**
6. 遇到未知的游戏函数、结构体偏移、场景名或 UI 节点名时，不得编造。应增加探针、日志、适配接口或安全失败路径，并把待确认项写入阶段报告。
7. 任何会移动、淘汰或写入猫数据的功能，默认必须可预览、可取消、可回滚；无法确认安全时只能进入只读模式。
8. 本阶段验收未通过时停止，不继续下一阶段。输出实际改动文件、测试结果、剩余风险和本地 commit 哈希。


## 固定技术基线

- 主路线：Windows x64 原生 DLL MOD。
- 运行时加载器：**Mewjector**。
- 游戏内 UI：**MewUI API**，以源码依赖方式编译进本 MOD。
- 可选安装管理器：Mewtator，仅用于安装和启停，不属于硬依赖。
- 参考实现：
  - Quick-Cleanup：参考“家园场景注入按钮并触发一次性操作”。
  - Mewgenics Breeding Manager：参考猫评分、血缘/近亲检查、房间优化、文件竞态处理；只能复用许可证允许的代码。
  - Online Savegame Editor：参考 `.sav` 解析、SQLite/LZ4、dirty tracking、备份和安全写回。
  - Mewgenics QoL Manager：仅参考批量筛选、房间移动、符号标记的交互思路。
  - MewgenicsModTool：仅作为“实时读取、推荐、cull 可行”的能力证据；未获许可时不得复制代码或资源。
- 不采用“自动组队策略”。战斗猫只按独立评分排序和标记，不分析职业搭配、站位或队伍协同。
- 两个主动按钮：
  1. 家园界面：`自动整理猫舍`。只有玩家点击后才分析、分类、淘汰和调整房间。
  2. 次日出征/选猫界面：`标记推荐战斗猫`。点击后只高亮高评分猫，不自动选队。

## 安全门槛

本阶段只有在以下条件全部满足时启用 Full 模式：

- 支持当前游戏 build。
- 稳定猫 ID、房间 ID 可用。
- 保护摘要未变化。
- 场景仍为同一个 `HouseReady generation`。
- 游戏未保存、未切场景、未进入休息流程。
- 备份成功。
- 预览计划哈希与执行计划一致。

任一失败则取消，不做部分猜测。

## 事务结构

```cpp
struct OperationPrecondition {
    uint64_t snapshot_id;
    uint64_t scene_generation;
    int game_day;
    std::string game_build_id;
    std::string plan_hash;
    std::string protection_digest;
};

struct UndoRecord {
    CatId cat_id;
    std::optional<RoomId> old_room;
    std::optional<RoomId> new_room;
    bool was_culled{false};
    std::vector<std::byte> minimal_original_state;
};

struct OperationJournal {
    std::string operation_id;
    OperationPrecondition precondition;
    std::vector<UndoRecord> records;
    std::string status;
};
```

## 执行顺序

为了降低不可逆风险：

1. 再次拍摄轻量校验快照。
2. 创建完整存档备份或运行时可恢复快照。
3. 写入 journal 状态 `Prepared`。
4. 先执行非破坏性房间移动。
5. 校验所有移动结果。
6. 再执行淘汰。
7. 校验猫数量、房间归属、保护猫仍存在。
8. 写 `Committed`。
9. 刷新 UI。

如果淘汰机制是“移动到垃圾桶/捐赠区”而非立即永久删除，应优先使用可恢复路径。

## 写入适配器

```cpp
class IGameWriteAdapter {
public:
    virtual Result<void> MoveCat(CatId cat, RoomId target) = 0;
    virtual Result<void> CullCat(CatId cat) = 0;
    virtual Result<void> RestoreCat(const UndoRecord&) = 0;
    virtual Result<void> RefreshHouseUi() = 0;
};
```

不得让规划器调用这些接口。

## 备份策略

优先顺序：

1. 运行时官方/游戏内可逆操作快照。
2. 当前 `.sav` 完整复制为带时间和 operation ID 的 `.savbak`。
3. sidecar journal。

保留最近 N 份，由配置控制。备份前后计算大小和哈希；复制失败则禁止淘汰。

## 回滚

- 移动失败：反向恢复已移动猫。
- 淘汰前失败：完整回滚移动。
- 淘汰中途失败：先尝试 `RestoreCat`；不支持时停止后续淘汰，标记 `ManualRecoveryRequired` 并提供备份路径。
- 不自动在游戏运行中覆盖存档，除非已验证安全恢复流程。默认提示用户退出到主菜单后使用恢复工具。

## 并发与竞态

执行器持有 MOD 内部互斥锁，但不能假设游戏不保存。每个小步骤前检查 `IsSaveInProgress()` 和 scene generation。若状态变化，停止。

## 用户确认

默认流程：第一次点击生成预览，预览面板点击 `执行整理` 才进行破坏性操作。允许高级配置开启单击执行，但必须仍创建备份，且 UI 明示“单击模式”。

## 审计日志

记录 ID、旧房间、新房间、角色、分数、淘汰原因、结果。普通日志可隐藏猫名；详细 journal 本地保存。

## 测试

- 写适配器 mock 的全部失败点。
- 备份失败。
- 保护摘要变化。
- 场景切换。
- 第 3 个移动失败。
- 第 2 个淘汰失败。
- 回滚失败。
- 重复执行同一 operation ID，应拒绝。

游戏内先使用专门复制的测试存档，先只移动，再只淘汰 1 只明确测试猫，最后才做组合测试。

## 验收标准

- 无成功备份时绝不淘汰。
- 执行前后保护猫数量和 ID 一致。
- 可查看操作日志和恢复说明。
- 失败不会继续执行后续动作。
- 支持“只移动不淘汰”安全模式。
