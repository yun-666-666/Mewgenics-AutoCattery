# 第 09 阶段：房间分配器与房间不足回退策略

## 文档定位

生成自动房间调整计划，覆盖房间少、繁育房不足、容量不足、幼猫和受保护猫等情况。本阶段只规划，不写入。

  - Mewgenics Breeding Manager：参考猫评分、血缘/近亲检查、房间优化、文件竞态处理；只能复用许可证允许的代码。
  - Online Savegame Editor：参考 `.sav` 解析、SQLite/LZ4、dirty tracking、备份和安全写回。
  - Mewgenics QoL Manager：仅参考批量筛选、房间移动、符号标记的交互思路。
  - MewgenicsModTool：仅作为“实时读取、推荐、cull 可行”的能力证据；未获许可时不得复制代码或资源。
- 不采用“自动组队策略”。战斗猫只按独立评分排序和标记，不分析职业搭配、站位或队伍协同。
- 两个主动按钮：
  1. 家园界面：`自动整理猫舍`。只有玩家点击后才分析、分类、淘汰和调整房间。
  2. 次日出征/选猫界面：`标记推荐战斗猫`。点击后只高亮高评分猫，不自动选队。

## 总体目标

在不触碰保护猫和特殊房间规则的前提下，把猫安排到尽可能合理的房间。规划器必须允许“部分成功”，不能因为理想布局做不到就崩溃或随意淘汰。

## 房间角色

在实际游戏字段允许的范围内，把房间抽象为：

- `BreedingRoom`
- `CombatStagingRoom`
- `KittenRoom`
- `GeneralRoom`
- `SpecialRoom`
- `UnavailableRoom`

若游戏没有专用战斗房，`CombatStagingRoom` 只是 MOD 规划标签：选择一个普通房间集中放高分战斗猫；不修改房间类型。

## 容量概念

- `hard_capacity`：游戏明确限制，绝不可超。
- `soft_capacity`：默认 4，只影响舒适度，允许在降级模式短期超出。
- `emergency_capacity`：配置上限，只有无法安置且用户允许时使用。

```json
{
  "room_planning": {
    "default_soft_capacity": 4,
    "allow_soft_overflow": true,
    "max_soft_overflow_per_room": 2,
    "never_exceed_known_hard_capacity": true,
    "prefer_single_combat_staging_room": true,
    "keep_breeding_pairs_together": true,
    "avoid_inbreeding_pairs": true,
    "keep_kittens_separate_when_possible": true,
    "allow_partial_plan": true
  }
}
```

## 规划优先级

从不可移动到可牺牲：

1. `FullyUnmanaged` / `NoMove` 猫保持原位，占用先扣除。
2. 特殊房间和游戏强制居民保持。
3. 核心繁育配对进入可繁育房。
4. 推荐战斗猫集中到战斗准备房。
5. 幼猫进入幼猫/普通安全房。
6. 繁育备用猫。
7. 普通备用猫。
8. 淘汰候选在执行淘汰前保持原位或移入合法溢出位，不用“移动失败”触发删除。

## 繁育房不足

假设有 `B` 个可繁育房：

- 先选择得分最高且近亲风险合格的最多 `B` 组配对。
- 每个房间只放一组核心配对，除非游戏规则和配置明确允许更多。
- 其余高分繁育猫进入 `BreedingReserve`，放普通房。
- 若没有有效配对，不强行把两只高分猫放一起。
- 无法读取关系数据时，默认不自动生成繁育配对，只保留现状并提示。

## 房间总量不足

分三档回退：

### Level 0：理想布局

所有猫不超过软容量，核心配对独立，战斗猫集中。

### Level 1：软溢出

允许普通/备用房间超过软容量，但不超过硬容量和 `max_soft_overflow_per_room`。优先不要挤压繁育房。

### Level 2：容量释放建议

如果仍无法放置，向执行计划请求从 `capacity_relief_candidates` 中淘汰最少数量。规划器只计算需要释放的槽位和候选顺序，不执行。

### Level 3：安全部分成功

若候选不足或都受保护：

- 不移动无法安全安置的猫。
- 应用其余安全移动。
- 报告 `UnplacedCats`。
- 禁止超硬容量、禁止删除受保护猫。

## 规划算法

建议先使用确定性的贪心 + 局部改进，而不是一次引入复杂求解器：

1. 冻结不可移动居民。
2. 计算每个房间剩余容量。
3. 生成繁育配对候选，按联合分排序。
4. 安排繁育房。
5. 选择战斗准备房：优先空余多、非繁育、非特殊、舒适度高。
6. 安排推荐战斗猫。
7. 安排幼猫和其他猫。
8. 尝试交换减少溢出和移动次数。
9. 生成差异计划。

目标函数可包含：违规惩罚（无限大）→ 未放置数 → 硬/软溢出 → 移动数量 → 角色分散度。

## 数据结构

```cpp
struct PlannedMove {
    CatId cat_id;
    RoomId from_room;
    RoomId to_room;

    int priority;

struct RoomPlan {
    uint64_t snapshot_id;
    std::vector<PlannedMove> moves;

```

## 最小移动原则

同等质量方案下优先移动更少猫，避免每次按钮都把整个猫舍打乱。若当前房间已经满足角色和容量，则保持不动。

## 测试矩阵

- 0 房间、1 房间、2 房间、足够房间。
- 无繁育房、1 个繁育房、多繁育房。
- 所有房间有不可移动猫。
- 所有猫都受保护。
- 幼猫数量超过一个房间容量。
- 推荐战斗猫数量大于战斗准备房容量。
- 已知硬容量和未知硬容量。
- 规划重复执行幂等：第二次 moves 应为空或最小。

## 验收标准

- 返回确定、可解释、可部分成功的计划。
- 从不超过已知硬容量。
- 房间少时不会因为异常直接清空猫。
- 淘汰建议数量是满足容量所需的最小值。
- 本阶段不写游戏状态。
