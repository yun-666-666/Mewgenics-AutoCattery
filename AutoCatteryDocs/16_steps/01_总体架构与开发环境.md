# 第 01 阶段：总体架构、开发环境与仓库骨架

## 文档定位

建立后续 15 个阶段共同依赖的工程骨架。本阶段只验证 DLL 能被加载、日志可用、配置可读取，不实现任何猫数据修改。


## 给 Codex 的通用执行规则

1. **只实施本文档对应的阶段**，不得提前实现后续阶段，也不得把多个阶段合并为一次大改动。
2. 开始前先检查当前仓库实际状态、已有提交、构建方式和本阶段依赖是否已完成；已有实现优先复用，不重复造轮子。
3. 允许联网查找与本阶段有关的公开资料来核实事实。本文档和外部资料都只能作为参考；游戏值、接口、偏移、场景与 UI 信息必须以当前仓库、当前游戏 build、本地只读探针或实机证据为准，不得照搬未验证内容或擅自改换技术路线。
4. 不修改游戏原始文件，不提交游戏二进制、反编译产物、个人存档、第三方闭源资产或未经许可的代码。
5. 每个阶段都必须：先读取相关文件 → 做最小修改 → 构建/测试 → 记录结果 → 创建一个本地 Git commit。**绝不自动 push 到 GitHub。**
6. 遇到未知的游戏函数、结构体偏移、场景名或 UI 节点名时，不得编造。应增加探针、日志、适配接口或安全失败路径，并把待确认项写入阶段报告。
7. 任何会移动、淘汰或写入猫数据的功能，默认必须可预览、可取消、可回滚；无法确认安全时只能进入只读模式。
8. 本阶段验收未通过时停止，不继续下一阶段。输出实际改动文件、测试结果、剩余风险和本地 commit 哈希。


## 固定技术基线

- 主路线：Windows x64 原生 DLL MOD。
- 运行时加载器：**Mewjector**。
- 游戏内 UI：**MewUI API**，以源码依赖方式编译进本 MOD。
- 可选安装管理器：Mewtator，仅用于安装和启停，不属于硬依赖。
- 参考实现：
  - Quick-Cleanup：参考“家园场景注入按钮并触发一次性操作”。
  - Mewgenics Breeding Manager：参考猫评分、血缘/近亲检查、房间优化、文件竞态处理；只能复用许可证允许的代码。
  - Online Savegame Editor：参考 `.sav` 解析、SQLite/LZ4、dirty tracking、备份和安全写回。
  - Mewgenics QoL Manager：仅参考批量筛选、房间移动、符号标记的交互思路。
  - MewgenicsModTool：仅作为“实时读取、推荐、cull 可行”的能力证据；未获许可时不得复制代码或资源。
- 不采用“自动组队策略”。战斗猫只按独立评分排序和标记，不分析职业搭配、站位或队伍协同。
- 两个主动按钮：
  1. 家园界面：`自动整理猫舍`。只有玩家点击后才分析、分类、淘汰和调整房间。
  2. 次日出征/选猫界面：`标记推荐战斗猫`。点击后只高亮高评分猫，不自动选队。

## 本阶段目标

- 建立可重复构建的 x64 DLL 项目。
- 接入 Mewjector 的最小入口和日志。
- 以源码依赖方式接入 MewUI API，但只初始化，不创建正式按钮。
- 固定目录、命名、错误码、配置版本和模块边界。
- 建立“只读优先、写操作后置”的安全原则。

## 非目标

- 不识别家园或出征场景。
- 不读取猫、不评分、不移动房间、不淘汰。
- 不解析或写回存档。
- 不加入正式 UI。

## 推荐开发环境

- Windows 10/11 x64。
- Visual Studio 2022 或 Build Tools，安装 MSVC x64、Windows SDK、CMake、Ninja（可选）。
- Git。
- Python 3.11+ 仅用于测试脚本和构建辅助，不进入运行时 DLL。
- 主项目建议 C++20；第三方 C 源码按其原始标准编译。

## 核心模块边界

```cpp
namespace autocattery {

struct InitContext {
    std::filesystem::path game_root;
    std::filesystem::path mod_root;
    std::string game_build_id;
};

enum class ModMode {
    ReadOnly,
    Full,
    CompatibilityDegraded
};

class Module {
public:
    virtual ~Module() = default;
    virtual const char* Name() const noexcept = 0;
    virtual bool Initialize(const InitContext&) = 0;
    virtual void Shutdown() noexcept = 0;
};

}
```

模块依赖必须保持单向：

```text
UI → Application Services → Domain/Scoring/Planning → Game Adapter/Persistence
                                            ↓
                                      Safety/Journal
```

UI 不得直接操作游戏内存；评分器不得直接读写场景节点；执行器不得自行决定评分规则。

## 错误模型

建立统一错误码，禁止仅用字符串判断：

```cpp
enum class ErrorCode {
    Ok,
    NotInitialized,
    UnsupportedGameBuild,
    SceneUnavailable,
    UiNodeNotFound,
    CatDataUnavailable,
    RoomDataUnavailable,
    SnapshotInvalid,
    ConfigInvalid,
    BackupFailed,
    WriteConflict,
    OperationCancelled,
    PartialSuccess,
    InternalError
};
```

所有高层操作返回：

```cpp
template<class T>
struct Result {
    T value{};
    ErrorCode code{ErrorCode::Ok};
    std::string message;
    explicit operator bool() const noexcept { return code == ErrorCode::Ok; }
};
```

## 初始配置

`config/default_config.json` 至少包含：

```json
{
  "schema_version": 1,
  "mod_enabled": true,
  "safe_mode": true,
  "log_level": "info",
  "language": "zh-CN",
  "ui": {
    "house_button_enabled": true,
    "embark_button_enabled": true,
    "show_debug_overlay": false
  },
  "safety": {
    "require_preview_before_destructive_actions": true,
    "create_backup_before_apply": true,
    "abort_on_unknown_game_build": true
  }
}
```

配置加载顺序：内置默认值 → `default_config.json` → 用户 `user_config.json`。未知字段保留并忽略，缺失字段使用默认值；schema 版本过高时进入只读模式。

## 日志要求

日志必须包含：时间、线程、模块、级别、事件 ID、game build、mod version。禁止记录完整个人路径和完整存档内容。示例：

```text
[INFO][Bootstrap][AC1001] AutoCattery 0.1.0 initializing; build=unknown
[WARN][Compatibility][AC1102] Build fingerprint unavailable; forcing read-only mode
```

## 需要创建的最小代码

- DLL 入口或 Mewjector 指定导出入口。
- `AutoCattery_Initialize()` / `AutoCattery_Shutdown()`。
- 模块注册器。
- 日志器。
- 配置加载器。
- 版本信息。
- MewUI API 的启动与关闭包装器。

入口不得做复杂工作，应启动初始化线程或延迟到安全的 scene-ready 回调，避免在 `DllMain` 中锁死加载器。

## 构建与部署脚本

`tools/build.ps1`：配置、编译 Debug/Release、输出到 `dist/`。

`tools/deploy.ps1`：只复制本 MOD 的 DLL、配置模板和许可证清单到游戏 `mods/AutoCattery/`，不得覆盖 Mewjector 或其他 MOD。

`tools/verify_install.ps1`：检查游戏根目录、Mewjector 文件、mods 目录、日志目录和 DLL 位数。

## 测试

1. 配置解析单元测试。
2. 无游戏环境下的模块初始化测试。
3. DLL 导出符号检查。
4. x64 架构检查。
5. 将空壳 DLL 部署到测试游戏后，启动/退出三次，确认不崩溃且日志每次只初始化一次。

## 验收标准

- Release 与 Debug 均可构建。
- DLL 被 Mewjector 加载并输出初始化/关闭日志。
- MewUI API 初始化失败时，MOD 自动降级并不影响游戏启动。
- 不改变任何猫、房间或存档。
- 生成 `docs/implementation-status.md`，记录游戏 build、Mewjector 版本、MewUI API commit 和本地测试结果。
