## 固定技术基线

- 主路线：Windows x64 原生 DLL MOD。
- 运行时加载器：**Mewjector**。
- 游戏内 UI：**MewUI API**，以源码依赖方式编译进本 MOD。
- 可选安装管理器：Mewtator，仅用于安装和启停，不属于硬依赖。
- 参考实现：
  - Quick-Cleanup：参考“家园场景注入按钮并触发一次性操作”。
  - Mewgenics Breeding Manager：参考猫评分、血缘/近亲检查、房间优化、文件竞态处理；只能复用许可证允许的代码。
  - Online Savegame Editor：参考 `.sav` 解析、SQLite/LZ4、dirty tracking、备份和安全写回。
  - Mewgenics QoL Manager：仅参考批量筛选、房间移动、符号标记的交互思路。
  - MewgenicsModTool：仅作为“实时读取、推荐、cull 可行”的能力证据；未获许可时不得复制代码或资源。
- 不采用“自动组队策略”。战斗猫只按独立评分排序和标记，不分析职业搭配、站位或队伍协同。
- 两个主动按钮：
  1. 家园界面：`自动整理猫舍`。只有玩家点击后才分析、分类、淘汰和调整房间。
  2. 次日出征/选猫界面：`标记推荐战斗猫`。点击后只高亮高评分猫，不自动选队。

## 前置条件

第 1 阶段已验收，MewUI API 可初始化，日志稳定。

## 目标

识别至少三类状态：

- `HouseReady`：玩家回家后可管理猫的家园主界面。
- `EmbarkSelectionReady`：玩家可以选择出战猫的界面。
- `UnsafeTransition`：加载、过场、保存、战斗、暂停菜单等不允许执行管理的状态。

## 设计原则

不要只依赖一个硬编码场景字符串。采用多信号判定：

1. MewUI scene-ready 回调的场景标识。
2. 必需 UI 节点是否存在。
3. 游戏状态/控制器指针是否有效。
4. 界面是否可交互。
5. 最近一次场景切换是否已稳定至少若干帧。

## 状态机

```text
Unknown
  ├─ scene ready + house signatures → HouseReady
  ├─ scene ready + embark signatures → EmbarkSelectionReady
  └─ loading/saving/battle → UnsafeTransition

HouseReady/EmbarkSelectionReady
  └─ scene unload or signature lost → UnsafeTransition → Unknown
```

定义：

```cpp
enum class UiContextKind {
    Unknown,
    House,
    EmbarkSelection,
    UnsafeTransition
};

struct UiContextSnapshot {
    UiContextKind kind;
    std::string scene_name;
    uint64_t scene_generation;
    bool input_enabled;
    bool save_in_progress;
    std::vector<std::string> matched_signatures;
};
```

`scene_generation` 每次场景卸载/加载递增，后续按钮和高亮都用它防止悬空指针。

## 场景签名表

新增 `config/scene_signatures.json`，支持多个候选：

```json
{
  "schema_version": 1,
  "house": {
    "scene_names": [],
    "required_nodes_any": [],
    "required_nodes_all": [],
    "forbidden_nodes": []
  },
  "embark_selection": {
    "scene_names": [],
    "required_nodes_any": [],
    "required_nodes_all": [],
    "forbidden_nodes": []
  }
}
```

初次开发时可为空，由探针日志记录候选，但不得因为空配置就把任意场景认定为家园。

## 探针模式

只在 `show_debug_overlay=true` 或 Debug 构建启用：

- scene-ready 时记录场景名。
- 枚举有限深度 UI 树，记录节点类型、名称、父路径和可见性。
- 对相同结构做哈希，避免每帧刷日志。
- 支持热键导出当前 UI 树摘要到 `diagnostics/`。
- 不导出纹理、脚本字节码或游戏资产。

## 需要实现的接口

```cpp
class SceneContextService {
public:
    Result<void> Start();
    void Stop() noexcept;
    UiContextSnapshot Current() const;
    uint64_t Subscribe(std::function<void(const UiContextSnapshot&)> callback);
    void Unsubscribe(uint64_t token);
};
```

回调必须在游戏允许的主线程或 UI 线程执行；若底层回调线程不确定，先排队到 `MainThreadDispatcher`。

## 去抖与幂等

- 同一 `scene_generation` 只发布一次 `HouseReady`/`EmbarkSelectionReady`。
- UI 节点短暂丢失 1–2 帧不立刻卸载，默认连续 10 帧丢失才降级。
- 场景稳定前不允许按钮注入。
- 卸载时先通知订阅者清理 UI，再释放适配器引用。

## 兼容失败策略

- 只匹配场景名但关键节点不匹配：记录警告，不进入 Ready。
- 关键节点匹配但场景未知：Debug 可标记候选，Release 仍不自动进入 Ready，除非配置允许结构匹配。
- 游戏 build 未知：场景识别可运行，但所有写操作保持禁用。

## 测试

使用纯 C++ 假适配器模拟：

1. 正常进入/离开家园。
2. 正常进入/离开出征选择。
3. 节点短暂闪烁。
4. 重复 scene-ready 回调。
5. 场景快速切换。
6. 保存中切换界面。
7. 回调订阅者抛出异常时不影响其他订阅者。

游戏内人工测试记录实际签名，但不得在本阶段创建按钮。

## 验收标准

- 日志能稳定区分家园、出征选择和不安全状态。
- 连续往返至少五次无重复订阅、无悬空访问、无崩溃。
- UI 树探针仅在显式调试模式运行。
- 所有状态变化都有 `scene_generation`。
