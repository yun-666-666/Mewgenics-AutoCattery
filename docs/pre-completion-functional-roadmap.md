- 每次进入 House 和每次生成计划前都会刷新当前运行时数据。
- MOD 会扫描存档候选，并按当前运行时猫数量选择相应存档，不再固定使用上个
  存档或最近修改的主存档。
- 当前 build 已确认普通房间 ID：
  - `Attic`
  - `Floor1_Large`
  - `Floor1_Small`
  - `Floor2_Large`
- 根据当前存档实际解锁情况支持 2、3、4 个房间，不要求所有房间都有猫。
- 自动分房按人数、公母、具体猫用途和房间实际属性建立稳定目标，不以是否
  战斗、是否战斗过、职业、受伤等状态排除普通分房候选。
- 可以从 `voice_id` 识别当前样本中的公母；高潜力目标组在条件允许时至少
  包含一公一母。
- 8 猫存档实机日志：正确选择 8 猫候选，计划移动 6 只，原生移动提交 6 只。
- 25 猫存档实机日志：正确选择 25 猫候选，计划移动 10 只，原生移动提交
  10 只。
- 已在目标房间的猫会跳过；重复执行提交 0 次，不重复移动。
- 2026-08-01 两房均衡实机结果：8 猫 `4/4`、25 猫 `13/12`。
- 25 猫三房 `9/8/8` 的属性目标、人数相同的手动换猫恢复和重复整理已由
  玩家确认通过。
- 次日战斗猫推荐、可点击猫详情、F10 设置与猫保护、备份和离线恢复源码工具已经

- 全部普通/进阶玩家职业的升级重骰次数已接入 F10 设置，范围 0–99，重启生效。

## 当前自动分房的准确边界

当前算法是可工作的“房间属性 + 具体猫目标 MoveOnly”版本：

1. 读取当前 House 对应的存档快照。
2. 用当前 build 的实时 CatId→房间映射覆盖尚未保存的旧房间分布。
   房间指针为 null 的 House 猫作为未分配来源处理，不把房外区域当作目标房。
3. 读取当前游戏家具定义，汇总房间舒适、刺激、健康、变异和吸引力。
4. 按全部实际房间计算均衡目标人数。
5. 按当前繁育/培养阶段和房间属性分配具体猫；公母足够时维持每房至少一公
   一母。
6. 用最小成本匹配执行确定目标；人数相同但猫换错房时仍会纠正。
7. 第二次点击前再次校验全体实时房间；变化时取消旧预览并保持零移动。
8. 状态一致时调用当前 build 已验证的原生房间移动函数。

它还不是完整的全猫舍最优分配器，也不执行真实淘汰。

## 剩余业务功能

### 1. 全房间分配优化（核心算法与三房实机验证完成）

- 已根据 2、3、4 个实际房间计算均衡目标猫数。
- 已避免猫少时“前 N 名等于全部猫”而把所有猫集中到阁楼。
- 已在已知公母数量足够时维持每个目标房至少一公一母。
- 已按实际房间属性分配具体猫；属性目标优先，移动数量只作为同目标下的
  次级成本。
- 读取或实测真实硬容量；未知容量不能用软配置冒充。
- 支持空房、满房、某一性别极少和部分房间未解锁。

### 2. 分阶段遗传与繁育目标

- 已实现第一阶段：家中尚不能稳定产出全属性 7 猫时，按七项基础属性
  的 7 点覆盖、双方稳定 7 项、游戏缓存 COI 和已解锁性取向选择成年配对。
- 未解锁显示功能的 25/8 猫档仍完整保存七项基础属性，故基础属性默认读取；
  性取向和亲缘的进度门来自 `tink_sexuality`、`tink_inbreeding`、
  `tink_relationships`，未解锁维度不读取、不评分。
- 当前稳定判定：存在一对可繁育成年猫，双方七项基础属性均为 7，且该配对
  的游戏缓存后代 COI 为 0。未达到时配对只看七维与 COI；达到后才启用遗传
  特征分，并把配对放入高刺激、其次高变异属性的房间。
- 主存档只读结果仍处于 FOUNDATION：最佳配对覆盖 6/7 项，其中 4 项双方
  均为 7；当前属性目标房为 `Attic`。该自动移动需玩家用测试副本确认。
- 第二阶段已实现：稳定全 7 配对保持双方全 7 与 COI 0 的硬底线，再按技能、
  被动、疾病、普通变异和出生缺陷的可配置权重排序。
- `SkillShare` 本身不按普通被动继承价值计分；疾病按父母各 15% 风险计罚；
  技能、被动和单方变异部位使用当前刺激值对应的继承概率或偏好。
- 当前公式来自可追溯的当前 build 逆向笔记，ID 分类来自本机当前
  `resources.gpak`；未确认的具体强弱不硬编码，默认等权且可按 ID 覆盖。

### 3. 保护规则接入实时移动

- 已撤销 MoveOnly 对全部猫统一允许移动的临时覆盖。
- sidecar 已支持完全不管理、禁止移动、禁止淘汰和指定猫固定房间；规划器与
  执行前置条件都会拒绝绕过固定房间或 NoMove。
- 保护文件在预览与执行前分别读取；两次点击之间变化会取消旧预览。
- 当前 build 尚未读取游戏原生收藏、锁定和特殊状态字段，因此这些来源不能
  假装已接入；需要保护的猫先使用 sidecar 明确设置。
- 通用保护管理器与 Release 部署已完成：自动发现存档和猫，以稳定猫指纹
  区分跨存档重复 CatId，改名或搬房不会丢失保护；只有玩家点击应用才写入。
- 默认规则为空，不针对任何玩家存档。游戏原生收藏/锁定/特殊状态字段只有在
  当前 build 得到真实证据后才接入，不能把猜测字段当作保护来源。
- 玩家已在测试存档中确认 NoMove、fixed_room 和移除规则全部通过。
- F10 游戏内设置/保护面板已经完成并部署；外部 EXE 已移除，当前只等
  玩家确认真实 House 画面、输入拦截和保护写入交互。

### 4. 淘汰功能

- 显示建议淘汰的猫、评分和原因。
- 玩家明确确认后才执行淘汰。
- 淘汰数量与真实容量和最低繁育/战斗种群联动。
- 保护猫永远不能进入可执行淘汰列表。
- 提供操作 journal、失败中止、撤销和恢复入口。

### 5. 可靠的存档身份匹配

- 当前按运行时猫数量选择存档，已经解决 8、25、79 猫存档切换问题。
- 若两个存档猫数相同，仍需比较完整运行时 CatId 集合或稳定存档指纹。
- 换存档后必须自动使旧预览失效，不能执行上个存档的计划。

### 6. 完整预览界面（当前移动预览已完成）

- 已在 F10 顶级页展示每只计划移动猫的来源房间、目标房间、潜力、性别和
  移动原因。
- 已展示整理前后各房间人数和公母比例，并显示未放置猫数量。
- 现有第一次点击预览、第二次点击只移动、状态变化取消的操作语义保持不变。
- “包含淘汰”、淘汰确认、淘汰失败/部分成功属于未来真实淘汰阶段，不伪装为
  已完成的移动预览功能。

### 7. 配置支持

- 阁楼目标猫数或比例。
- 各房间目标人数与用途。
- 公母最低数量或比例。
- 属性、技能、被动、变异和负面特征的权重。
- 全 7 培育阶段与技能/变异优化阶段的自动切换条件。
- 保护、淘汰、备份和恢复选项。

## 尚需实机验证

- 解锁完整信息的存档副本中，推荐繁育配对被共同放入属性目标房，并且重复
  整理为 0 次移动。
- 未解锁性取向/亲缘的 25 猫和 8 猫测试档继续正常分房，不启用隐藏配对。
- 房外猫进入普通房间，并在整理完成后保持幂等。
- 4 房主存档的完整自动分配。
- 自动分房后触发游戏正常保存，退出并重新进入后结果仍然存在。
- 两个猫数相同的存档之间切换。
- 性别极端失衡、空房、满房和原生房间拒绝接收的情况。

## 不属于缺失功能

- 不自动组建出征队伍。
- 不自动休息或推进天数。
- 不自动选择出征。
- 猫是否战斗、是否战斗过、职业或受伤状态不作为潜力分房的排除条件。
