### 存档快照

- 只读 SQLite 存档发现与候选扫描。
- LZ4 猫 blob 解析。
- 当前 House CatId、房间字符串和七项属性读取。
- 遗传属性、遗传加成、装备加成、职业和原始技能槽读取。
- 从 `voice_id` 提取当前样本的公母信息。
- 每次进入 House 和每次预览前刷新运行时上下文。
- 按当前运行时猫数量选择对应存档，解决 8、25、79 猫存档切换串档。
- 当前 build 会读取全体实时 CatId、组件和房间指针，并覆盖尚未写回存档的
  `house_state` 房间分布。
- 当前房间指针为 null 的 House 猫会保留 CatId/组件身份，并作为房外未分配
  猫参与规划；房外区域本身不会成为自动分房目标。
- 七项基础属性区块在未解锁显示功能的 25/8 猫档中也完整存在，因此默认
  读取；性取向和亲缘仍从 `npc_progress` 的真实进度门启用，未解锁就保持
  未知且不参与评分。
- 同一 House generation 缓存物理房间指针到房间 ID 的映射；批量或手动搬猫
  后不再根据尚未保存的旧住户分布重新给物理房间改名。
- 主存档已只读确认 `pedigree` 三张表：当前 79 只猫的 3160 个无序配对
  （含自身）都有游戏缓存 COI；性取向样本为异性恋 60、双性恋 9、同性恋
  10，两个前期测试档均保持未知。

### 评分与规划

- 七项基础属性的确定性潜力评分与排序；繁育不再把后天/装备修正计入
  可遗传基础属性。
- 当前 MoveOnly 模式不使用战斗状态、是否战斗过、职业和受伤状态排除猫。
- 前 N 名潜力组选择并分散到当前可用房间。
- 2、3、4 房人数均衡；目标人数最大相差 1。
- 已知公母足够覆盖各目标房时，每个至少 2 只的房间保留一公一母。
- 使用最小成本匹配恢复确定的属性目标，人数相同或具体猫被换房也会纠正。
- 解锁完整繁育信息后，筛选成年且性取向可行的配对，先最大化七维中可达到
  7 的覆盖和双方都为 7 的稳定项，再考虑游戏缓存 COI。
- 未稳定全 7 时只按基础属性与 COI 配对。双方全 7 且配对 COI 为 0 后，才
  启用技能、被动、疾病、普通变异和出生缺陷遗传评分。
- 稳定阶段使用当前房间最高刺激值计算技能/被动和变异部位的继承偏好；繁育
  房按刺激、变异、舒适顺序选择。
- 变异 ID 从猫 blob 的 15 个主部位槽读取，并由当前 build 的
  `data/mutations/*.gon` 分类；低 ID 基础部位不冒充变异，`birth_defect`
  标签与缺失部位哨兵分类为出生缺陷。
- 当前 MoveOnly 不把软配置容量当作游戏硬容量；容量未知时保留限制并依赖
  当前 build 原生移动门最终拒绝。
- 当前已确认普通房间：
  - `Attic`
  - `Floor1_Large`
  - `Floor1_Small`
  - `Floor2_Large`
- 根据运行时房间组件推导当前可用 2、3、4 房集合。
- 规划器支持原生目标容量拒绝、部分计划和幂等重复执行。

### 当前 build 原生移动

已验证的当前 build 运行时事实：

- `HouseCat` 对象大小边界：`0x118`。
- `HouseCat` vtable RVA：`0xEF4F58`。
- CatId：`HouseCat+0x80`。
- 当前房间指针：`HouseCat+0xE8`。
- 原生 House 房间移动 RVA：`0x2E7DB0`。
- 调用后独立确认 `HouseCat+0xE8` 指向目标房间。

执行流程：

1. 第一次点击读取当前存档并生成计划。
2. 第二次点击重新绑定运行时 HouseCat 和房间对象。
3. 执行前比较预览与全体实时 CatId→房间映射。
4. 若玩家在预览后手动搬猫，旧预览失效并保持零移动。
5. 状态未变化时，其余猫通过游戏原生房间移动函数执行。
6. 日志记录提交数量。
