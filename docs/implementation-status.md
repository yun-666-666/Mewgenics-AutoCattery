### 存档快照

- 只读 SQLite 存档发现与候选扫描。
- LZ4 猫 blob 解析。
- 当前 House CatId、房间字符串和七项属性读取。
- 遗传属性、遗传加成、装备加成、职业和原始技能槽读取。
- 从 `voice_id` 提取当前样本的公母信息。
- 每次进入 House 和每次预览前刷新运行时上下文。

- 当前 build 会读取全体实时 CatId、组件和房间指针，并覆盖尚未写回存档的
  `house_state` 房间分布。

### 评分与规划

- 七项属性的确定性潜力评分与排序。
- 当前 MoveOnly 模式不使用战斗状态、是否战斗过、职业和受伤状态排除猫。
- 前 N 名潜力组选择并分散到当前可用房间。
- 2、3、4 房人数均衡；目标人数最大相差 1。
- 已知公母足够覆盖各目标房时，每个至少 2 只的房间保留一公一母。
- 使用最小成本匹配优先减少移动，再平衡潜力分布。
- 当前 MoveOnly 不把软配置容量当作游戏硬容量；容量未知时保留限制并依赖
  当前 build 原生移动门最终拒绝。
- 当前已确认普通房间：
  - `Attic`
  - `Floor1_Large`
  - `Floor1_Small`
  - `Floor2_Large`
- 根据运行时房间组件推导当前可用 2、3、4 房集合。
- 规划器支持原生目标容量拒绝、部分计划和幂等重复执行。

### 当前 build 原生移动

已验证的当前 build 运行时事实：

- `HouseCat` 对象大小边界：`0x118`。
- `HouseCat` vtable RVA：`0xEF4F58`。
- CatId：`HouseCat+0x80`。
- 当前房间指针：`HouseCat+0xE8`。
- 原生 House 房间移动 RVA：`0x2E7DB0`。
- 调用后独立确认 `HouseCat+0xE8` 指向目标房间。

执行流程：

1. 第一次点击读取当前存档并生成计划。
2. 第二次点击重新绑定运行时 HouseCat 和房间对象。
3. 执行前比较预览与全体实时 CatId→房间映射。
4. 若玩家在预览后手动搬猫，旧预览失效并保持零移动。
5. 状态未变化时，其余猫通过游戏原生房间移动函数执行。
6. 日志记录提交数量。
