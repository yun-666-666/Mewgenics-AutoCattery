# AutoCattery 当前实现状态

更新日期：2026-08-09

## v0.5.46 家具 stable-key 生命周期隔离

- 当前 House scene 内，刚退回仓库或失败回收的 stable key 会保持 quarantine；家具
  分析和原生创建入口都不会再次使用它。新 House scene 才清空隔离。
- 玩家启动自动放置后，每项事务完成会自动刷新、重新分析并继续当前场景内其他安全
  操作，不再要求每替换一件就手动重新分析。
- 不再逆向重建之前已提交的属性替换；原生 SEH 后当前场景停止所有后续家具写入。
- Release 聚焦测试和 DLL 编译通过；实机验证待玩家完成。

本文件只陈述当前实现。各阶段报告保留为历史证据；其中“PreviewOnly”“真实
移动未接通”等结论描述的是当时状态，已经被后续运行时逆向和玩家验证取代。

## 当前游戏与加载边界

- 平台：Windows x64。
- Loader：Mewjector v3。
- UI：MewUI API 1.2.0。
- 启动时只确认游戏目录存在正规的 `Mewgenics.exe`，不再用固定大小或 SHA-256
  阻止 MOD 启用。
- 原生适配器仍在每次探针、房间读取和移动调用前检查指针、组件和结果；未来
  build 改变内部布局时，相关动作安全失败并保留只读面板与预览。

### 基础与 UI

- 模块注册、结构化日志、JSON 配置和热重载。
- House/过渡场景识别与 generation 生命周期。
- House 自动整理按钮。
- 次日战斗猫推荐列表和可点击猫详情。
- 普通 House 保留“自动整理猫舍”和“标记推荐战斗猫”及原有点击行为；仅当
  已验证的 `FurnitureBuildingUI` 组件出现时，同一对按钮切换为“自动放置”和
  “开始分析”。Stage 39 的“开始分析”会生成同房间布局计划；存在安全移动时
  启用“自动放置”，随后每个 UI tick 原生提交一件。离开家具模式后旧计划和分析
  结果立即失效，不会覆盖普通 House 推荐列表。
- F10 游戏内设置与猫保护；不再构建或发布外部设置 EXE。
- F10 可配置全部 14 个玩家职业的升级重骰次数（0–99，默认 3，重启生效）。
  写入与部署会动态同步同级已安装的 `SkillsPassivesFirstData` 普通与进阶职业
  补丁，因此控制面板改成任意值后，两套补丁保持一致，不再由旧的 3 覆盖。
- 存档选择界面会重置次日战斗推荐可用状态；残留的 `Battle`/`Map` 场景不会再
  让新选择的 8 猫存档继承上一局“当天已出征”的禁用状态。
- F10 完整预览页：逐猫来源、目标、性别、潜力和移动原因；各房间整理前后
  人数及公母比例。
- 中文/英文手动切换并持久化，默认中文。
- 默认关闭的本地猫技术数据收集；隐私字段明确排除。玩家可手动压缩并附加到
  GitHub Issues，MOD 本身没有自动上传路径。

  不再触发 `HOUSE.RECOMMEND_ROW` 本地化键回退或按名称重复查找，消除猫数量

  资源的组件根；不读取全部 4,249 个组件类型，正常渲染期间不重复扫描。
  F10 挂载失败从每帧重试降为每 500 ms 最多一次。
- 当天战斗推荐不可用时只在状态变化时同步一次，不再每帧重复清空推荐行；
  推荐行文本通过挂载时缓存的文字节点直接写入，不再触发全场景扫描。
- F10 打开期间只隐藏并禁用已挂载的整理与推荐按钮，不再卸载；关闭 F10 后
  直接恢复原注册，避免对过期 House UI 根再次查找和注册。

### 存档快照

- 只读 SQLite 存档发现与候选扫描。
- LZ4 猫 blob 解析。
- 当前 House CatId、房间字符串和七项属性读取。
- 遗传属性、遗传加成、装备加成、职业和原始技能槽读取。
- 从 `voice_id` 提取当前样本的公母信息。
- 家具分析按运行时完整 CatId 集合选择当前存档，退化路径才使用 House 猫数量；
  每次玩家点击重新读取全部家具、当前 day、动态房间集合和当前资源目录。
- 家具分析快照绑定 scene generation、匿名存档身份、猫房间、每件家具实例的
  原始字段、房间几何、家具信息 opaque payload 和效果目录。未识别空房使用匿名
  运行时槽，不把旧四房数组带入家具分析服务。
- 每次进入 House 和每次预览前刷新运行时上下文。
- 按当前运行时猫数量选择对应存档，解决 8、25、79 猫存档切换串档。
- 当前 build 会读取全体实时 CatId、组件和房间指针，并覆盖尚未写回存档的
  `house_state` 房间分布。
- 当前房间指针为 null 的 House 猫会保留 CatId/组件身份，并作为房外未分配
  猫参与规划；房外区域本身不会成为自动分房目标。
- 大型 MoveOnly 计划每个 UI tick 最多提交 8 次原生移动；每批后重新捕获实时
  房间并生成新预览。离开 House、存档切换或 generation 改变会停止后续批次。
- 七项基础属性区块在未解锁显示功能的 25/8 猫档中也完整存在，因此默认
  读取；性取向和亲缘仍从 `npc_progress` 的真实进度门启用，未解锁就保持
  未知且不参与评分。
- 同一 House generation 缓存物理房间指针到房间 ID 的映射；批量或手动搬猫
  后不再根据尚未保存的旧住户分布重新给物理房间改名。
- 主存档已只读确认 `pedigree` 三张表：当前 79 只猫的 3160 个无序配对
  （含自身）都有游戏缓存 COI；性取向样本为异性恋 60、双性恋 9、同性恋
  10，两个前期测试档均保持未知。

### 评分与规划

- 七项基础属性的确定性潜力评分与排序；繁育不再把后天/装备修正计入
  可遗传基础属性。
- 当前 MoveOnly 模式不使用战斗状态、是否战斗过、职业和受伤状态排除猫。
- 前 N 名成年潜力组优先进入高健康、高舒适的战斗驻留房；幼猫不再被潜力角色
  拉入战斗房。
- 2、3、4 房人数均衡；目标人数最大相差 1。
- 不再对全部房间强制一公一母；只有确认一公一母推荐繁育对后，才对独立繁育
  目标房按可用公母建立最佳可达的基本均衡。固定房和不可移动居民先计入，无法
  达到 1:1 时安全降级。战斗、训练和普通功能房完全不因性别比例替换或搬猫。
- 使用最小成本匹配恢复确定的属性目标，人数相同或具体猫被换房也会纠正。
- 解锁完整繁育信息后，只筛选已知一公一母且性取向可行的成年配对，先最大化七维中可达到
  7 的覆盖和双方都为 7 的稳定项，再考虑游戏缓存 COI。
- 首选配对进入繁育房后，其余可移动槽位按整个同房群体优化：每只候选猫必须
  与已选全部异性猫都有合格配对证据，再优先最大化最弱交叉配对分数、最小化
  最坏后代 COI、最大化平均配对分数。这样适配游戏实际从同房猫中交叉选配，
  仍不保证锁定某一对。
- 未稳定全 7 时只按基础属性与 COI 配对。双方全 7 且配对 COI 为 0 后，才
  启用技能、被动、疾病、普通变异和出生缺陷遗传评分。
- 繁育房先避开舒适 `≤ -10` 的自动失败环境，再以舒适与刺激的较低项保证两者
  不出现明显短板；稳定阶段再把房间 Mutation 作为额外同分依据。
- 开启“尽量分开幼猫”且繁育房、战斗驻留房之外仍有可用房间时，MoveOnly
  会把可移动幼猫集中到高健康、高舒适的育幼目标；固定与不可移动居民优先。
- 变异 ID 从猫 blob 的 15 个主部位槽读取，并由当前 build 的
  `data/mutations/*.gon` 分类；低 ID 基础部位不冒充变异，`birth_defect`
  标签与缺失部位哨兵分类为出生缺陷。
- 当前 MoveOnly 不把软配置容量当作游戏硬容量；容量未知时保留限制并依赖
  当前 build 原生移动门最终拒绝。
- 当前已确认普通房间：
  - `Attic`
  - `Floor1_Large`
  - `Floor1_Small`
  - `Floor2_Large`
- 根据运行时房间组件推导当前可用 2、3、4 房集合。
- 规划器支持原生目标容量拒绝、部分计划和幂等重复执行。

### 当前 build 原生移动

已验证的当前 build 运行时事实：

- `HouseCat` 对象大小边界：`0x118`。
- `HouseCat` vtable RVA：`0xEF4F58`。
- CatId：`HouseCat+0x80`。
- 当前房间指针：`HouseCat+0xE8`。
- 原生 House 房间移动 RVA：`0x2E7DB0`。
- 调用后独立确认 `HouseCat+0xE8` 指向目标房间。

执行流程：

1. 第一次点击读取当前存档并生成计划。
2. 第二次点击重新绑定运行时 HouseCat 和房间对象。
3. 执行前比较预览与全体实时 CatId→房间映射。
4. 若玩家在预览后手动搬猫，旧预览失效并保持零移动。
5. 状态未变化时，其余猫通过游戏原生房间移动函数执行。
6. 日志记录提交数量。
