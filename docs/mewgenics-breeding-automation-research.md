# Mewgenics 繁育与房间自动化研究

更新日期：2026-08-05

本文把公开教程、当前 build 逆向资料和本仓库已验证数据分开记录。公开攻略只
用于提出策略；游戏字段、概率、房间 ID、变异 ID 和写入能力仍以当前仓库、
当前游戏资源、只读探针和玩家实测为准。

## 资料来源

### A. 当前繁育函数逆向笔记（高置信度机制依据）

- SciresM, *Mewgenics breeding notes*：
  <https://gist.github.com/SciresM/95a9dbba22937420e75d4da617af1397>
- 笔记明确说明其来源是对 `glaiel::CatData::breed` 的代码分析，而不是 GPAK
  文本猜测；页面在 2026-04-23 仍有更新。
- 可直接用于当前评分模型的结论：
  - 七项基础属性逐项从父母选择；选择较高值的概率为
    `(1 + 0.01 * Stimulation) / (2 + 0.01 * Stimulation)`。
  - 第一技能继承概率为 `0.20 + 0.025 * Stimulation`，32 刺激时封顶。
  - 第二技能继承概率为 `0.02 + 0.005 * Stimulation`。
  - 被动继承概率为 `0.05 + 0.01 * Stimulation`；`SkillShare` 本身不进入
    普通被动继承池。
  - 父母双方各有固定 15% 的疾病/障碍继承风险，不受家具属性影响。
  - 变异属于身体部位变体；单方拥有变异时，也使用与较高基础属性相同的刺激
    偏好公式。
  - 近交会提高出生缺陷疾病和出生缺陷部位风险，因此 COI 不能被普通收益抵消。
- 边界：该笔记没有给出 Health、Mutation 房间属性触发每日事件的完整公式；
  这些数值只做方向性用途排序，不能伪造精确概率。

### B. Steam 社区《Breeding Basics》（中等置信度、多人使用的基础教程）

- <https://steamcommunity.com/sharedfiles/filedetails/?id=3664011595>
- 与当前游戏 UI 和本地家具数据一致的方向性说明：
  - 高 Comfort 提高繁育倾向，低 Comfort 提高打架倾向。
  - 每个房间超过前 4 只猫后，教程称每多一只会降低 1 点 Comfort；粪便也会
    降低 Comfort。当前 MOD 只把“超过 4 只的拥挤舒适惩罚”用于软排序，不把它
    当作游戏硬容量。
  - Stimulation 影响基础属性、技能和被动遗传。
  - Health 低时有疾病传播、老猫死亡等风险；高 Health 有利于恢复和寿命。
  - Mutation 提高产生变异的倾向。
  - Appeal 是全屋属性，主要影响流浪猫质量，不应作为单个房间用途判定依据。
  - 推荐把繁育、幼猫和战斗猫分房；Fight Club 可能造成受伤和死亡。
- 边界：具体阈值和“最佳房间”是作者建议，不作为硬编码事实。

### C. Steam 社区《Meta Breeding Guide》（社区策略参考）

- <https://steamcommunity.com/sharedfiles/filedetails/?id=3672568623>
- 可转化为保守自动化目标的策略：
  - 前期优先积累刺激家具；繁育房需要同时维持可繁育的 Comfort。
  - 稳定后把目标技能引入血系，再逐步提高七项基础属性。
  - 达到稳定全 7 后，再筛选技能、被动、普通变异和可接受疾病。
  - 可设置单独的高 Comfort、高 Mutation 房筛选新变异，但不要让大量普通猫
    淹没该房间。
  - Fight Club 是可选风险玩法，不应由通用自动整理默认启用。
- 边界：文中多处使用 “I think”“I recommend”，属于个人流派。具体技能、
  职业、疾病和变异强弱必须保持玩家可配置，不能固化为唯一答案。

### D. Jay Dunna 视频教程（布局交叉验证）

- *Best CAT BREEDING GUIDE for Beginners in Mewgenics*：
  <https://www.youtube.com/watch?v=qXABbd9157E>
- 视频章节明确区分 House Stats、Breeding Room、Mutation Room、Fight Club、
  多房/少房布局、Family Tree 和早期收集变异；说明中推荐阁楼作为繁育房的

- 自动化不能按房间名称固定阁楼；必须读取当前实际家具属性，因为玩家布局会

## 证据合并后的阶段模型

### 1. 基础血系阶段（FOUNDATION）

- 配对硬条件：成年、可繁育、已知能产幼猫的公母组合、性取向兼容、COI 可读。
- 配对顺序：先最大化七项中可达到 7 的覆盖，再提高双方同时为 7 的稳定项，
  最后降低游戏缓存 COI。
- 房间目标：在可用普通房间中，先排除自动失败的低 Comfort 环境，再兼顾
  Comfort 与 Stimulation，避免只因单项极高就选中明显短板房。
- 技能、被动、疾病和变异不能覆盖基础血系目标。

### 2. 单只全 7 但未稳定阶段（BASE_ALL7）

- 仍以复制七项全 7、补齐第二只无近交全 7 配偶为目标。
- 不因为某只猫有好技能或变异而牺牲“双方全 7 + COI 0”的稳定条件。
- 新出生幼猫尽量进入独立育幼房，便于观察并减少与成年繁育群混杂。

### 3. 稳定全 7 阶段（STABLE_ALL7）

- 硬底线：推荐配对双方七项基础属性全部为 7，且该配对后代 COI 为 0。
- 在硬底线内，按当前刺激对应的真实继承公式计算技能、被动和单方变异价值；
  疾病和出生缺陷作为负面项。
- 具体技能/被动/变异默认等权，玩家可在 F10 配置中逐 ID 覆盖。公开攻略中的
  “最强技能/变异”只提供调参候选，不进入默认硬编码。
- 稳定阶段的繁育房仍需 Comfort 与 Stimulation 可用；Mutation 只作为额外
  同分依据，不能把低 Comfort 风险房变成默认繁育房。

## 房间用途自动判定

| 用途 | 优先属性 | 必须避免 | 当前自动化行为 |
|---|---|---|---|
| 繁育房 | Comfort 与 Stimulation 无明显短板；稳定全 7 后再看 Mutation；Health 作为后续同分项 | Comfort 自动失败边界、只靠单项极高取胜 | 放置推荐对及兼容繁育群；每个新增交叉配对的七项覆盖不低于推荐对，不再用普通猫填满空位；保护与容量限制优先 |
| 战斗驻留房 | Health、Comfort，其次 Stimulation | 占用繁育房；把幼猫或推荐繁育对当普通战斗猫 | 放置成年战斗推荐猫；不自动制造低 Comfort Fight Club |
| 育幼房 | Health、Comfort，其次 Stimulation | 繁育房、战斗驻留房、保护/固定房冲突 | 配置开启且有第三个可用房时集中可移动幼猫 |
| 普通/储备房 | 人数均衡、保护规则、最少必要移动 | 越过硬容量或原生移动拒绝 | 承接其余猫，保持幂等 |
| Mutation 筛选房 | 高 Comfort、高 Mutation | 未稳定全 7时抢占核心繁育资源 | 当前阶段只记录为后续多繁育房策略，不自动启用 |
| Fight Club | 低 Comfort | 受伤和死亡风险 | 永不默认启用；未来只能由玩家明确锁定房间用途 |

Appeal 只作为全屋吸引流浪猫的属性，不参与单房用途比较。

## 保留、移动与淘汰边界

- 推荐繁育对、繁育核心/储备、战斗推荐、幼猫、NoMove、fixed_room 和完全不
  管理规则必须在规划中保持可追溯。
- 未知性取向、亲缘、繁育资格、保护、身份或房间能力时安全失败，不猜测。
- 当前只执行原生 MoveOnly；真实淘汰、自动日结、自动休息、自动出征和自动
  组队继续禁用。
- “保留优秀变异/技能”当前表现为配对排序、保护建议和房间放置，不等于自动
  删除其他猫。真实淘汰必须有独立预览、确认、journal 和撤销阶段。

## Stage 27 实现验收

- 低 Comfort、高 Stimulation 房不会仅凭刺激成为繁育房。
- 推荐繁育对优先进入综合 Comfort/Stimulation 更合适的房间。
- 战斗推荐成年猫使用独立的高 Health、高 Comfort 驻留房，且性别不参与该房
  的分配。
- 开启“尽量分开幼猫”并存在额外可用房时，幼猫进入高 Health、高 Comfort
  育幼房，移动原因可审计为 `kitten-nursery-room`。
- 保护和固定居民优先；角色槽不足时安全降级，不产生无符号下溢或不可实现的
  角色数量。
- 重复整理已稳定布局时生成 0 次移动。
